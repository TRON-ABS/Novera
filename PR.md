# fix(sharing): use portable attachment names across share targets

Opening an exported HTML file from WhatsApp fails with ERR_FILE_NOT_FOUND even though its received copy exists. The observed transfer name contains mojibake and the browser URL encodes the œ sequence differently again. Copying the same document to the desktop opens successfully; the HTML embeds its images and Novera has not deleted its source.

Use ASCII attachment names at the common native share/file-copy and browser Web Share boundaries. Transliterate accents and Latin ligatures, replace spaces/special characters, bound the stem, avoid Windows device names and fall back to Novera for titles without usable Latin characters. Keep the real extension, Unicode document title/content, original media reference and local Save suggestion. Both browser capability detection and actual handoff use the same name. This covers the shared route to all OS targets rather than a WhatsApp-specific branch.

Validation: 99 Vitest tests in seven files with Windows configuration, including the observed encoding failure, non-Latin names, supported extensions, native/browser payloads, exports and the share component; TypeScript; Windows Vite build. Native/browser contracts also passed with macOS, Linux, Android and iOS configurations (seven tests passed and one Windows-only test skipped per configuration). These verify source behavior and contracts, not actual delivery in every messenger or device. No new Novera application binary, OS setting change or automatic send. Existing received attachments are unchanged; new handoffs require rebuilding Novera. Depends only on main; no issue closure.

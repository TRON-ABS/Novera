# feat(creation): install recommended media bundles and manage imported configurations

Image creation required a manually selected sd-cli executable from a developer build directory. The starter advice also sent users to three independent downloads and did not keep their complete configuration in the imported-model library.

Windows builds now stage the pinned private CUDA 13.4.3/Vulkan/CPU image launcher and its libraries/notices. Empty executable settings resolve to the bundled engine; explicit overrides remain available. A confirmed starter installer shows files, provider licences, disk space and a system Documents/custom destination before creating anything. Native downloads run in the background, resume with checked HTTP ranges, verify pinned SHA-256, and preserve conflicting existing files. A main-bar icon shows byte-weighted progress and stays ready until explicitly acknowledged, without sound, toast or OS notification.

Verified configurations are registered as one Image entry in the llama.cpp import page. The same page supports manual Image/Video import, validated editing, selection and removal with the existing imported-model semantics (files stay on disk). The conversation model selector includes these configurations by category. Generation resolves the configuration selected in its own thread; media weights are not passed to the causal-text engine. Deleted entries are not silently resurrected by download polling.

Validation: 98 targeted Vitest tests across eight files, TypeScript without emission, 70 complete locale catalogs at 1,681 keys, architecture checks/seven tests, native cargo check and six isolated Rust tests against the exact production module with tiny loopback HTTP fixtures. The full legacy native test runner encounters an environment DLL entry-point conflict; the isolated harness avoids the text-engine DLL dependency. CUDA engine build and real device probe passed. End-to-end GUI installation of the 5.27 GB bundle and generation through the newly bundled CUDA engine remain for the maintainer's next application build. Source publication and showcase updates are authorized. No application rebuild, complete model download, binary release or CI activation. The pinned model metadata was read from the official Hugging Face API; no credentials or private model data were published.

The optional official BFL FLUX NVFP4 starter requires a real tiny FP4 kernel probe in the configured Python runtime and reported free VRAM. It retains the Qwen GGUF CPU encoder. The native image path retains only its supported Qwen3 GGUF encoder.

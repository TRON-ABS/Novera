# fix(macos): defer GPU discovery until model loading

On Intel macOS, the worker initializes GPU backends before reading its preset or reporting its listening port. Cold startup exceeded the unchanged 30-second supervisor deadline in two CI attempts, including the missing-preset error path. Move backend registration into the native Engine startup and device enumeration entry points. Their existing once guard is retained, so model loads and device listing still initialize every required backend, while an idle worker and invalid preset avoid GPU discovery. Keep the production handshake deadline and all supervision assertions.

Add target=macos-tests to validate Intel and Apple Silicon separately: exact built-app/DMG/updater contents, packaged helpers, signed native replacement and tamper rejection, synthetic user-data preservation, 226 frontend regressions and the existing real-model engine/HTTP/supervision suites. The pinned 105 MB SmolLM2 fixture has enough context for the KV-persistence tests and is never shipped. Correct the macOS process probe to use ps instead of Linux /proc; omit Apple credential variables entirely in direct-distribution mode to prevent an empty certificate import. Retain packages in failure diagnostics.

Intel passed 187 engine unit tests, nine engine smoke tests, all 18 HTTP tests, nine migration tests and the frontend suites, but failed the initial worker startup deadline. A second Intel-only attempt reproduced the first-start failure; subsequent supervision tests passed. The new lazy-backend production fix requires fresh complete validation on both architectures; earlier artifacts are historical and cannot serve as validation of the changed worker.

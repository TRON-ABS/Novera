# fix(distribution): validate Windows ARM64 at application version 1.0.0

Windows ARM64 is built and cryptographically verified, but its actual Settings UI and public update target are not certified. Add a disposable native ARM64 installation/UI lane and prepare the additive Windows ARM64 publication without changing the application version or existing immutable Windows/Linux assets.

The `validate-arm64` target installs the exact staged NSIS, exercises native replacement and preservation checks, then drives the actual installed ARM64 WebView2 through the documented Playwright CDP connection. A fresh profile and loopback diagnostic port belong only to the CI child process. WebView2 ignores diagnostic environment flags in elevated processes, so a guarded launcher uses a linked or restricted medium-integrity user token and verifies the actual child integrity level without changing machine policy. No shipped binary, IPC service or privacy setting is mocked or modified. Local, x64 and self-hosted executions are refused.

The public verifier supports reviewed per-platform URLs across the canonical and supplemental releases. It preserves x64/Linux desktop and CLI links, rejects other repositories/versions, checks the combined nineteen files and all five payload signatures. The ARM64 feed is prepared privately; publication waits for the native result.

Local validation: nine targeted Node tests, eleven Python tests, Node/Python syntax, C# launcher compilation, actionlint and diff checks pass. The launcher is not invoked locally; its local refusal guard is tested. The exact ARM64 installer again passes `ci-check-updater.mjs --publication-check`; its SHA-256 is `85cab2cb6ececd8d85cb9198769a5076f03ba72c3847ab857af9b3406762a3f3`. The first native run 41455224313 reached the real ARM64 app but failed to attach CDP under the elevated runner account. Installation receipts are now retained before the separate UI check. The corrected standard-user lane and later public UI results will be recorded only after execution.

ARM64 ships the native CPU text engine, excluding the x64 CUDA image runtime. Updater signing is not Authenticode. Onboarding, all models, a CLI ARM64 build and an upgrade between two public versions are outside these checks. The portable distribution follows separately.

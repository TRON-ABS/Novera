# fix(release): align Android and CLI with Novera branding

Android initially had no startup window, lost provider secrets through an in-memory backend, retained the Tauri launcher, and reopened the keyboard when reasoning began. The CLI still shipped as jan.exe/jan despite the Novera product name.

Create and verify the Android startup window, persist secrets in encrypted private app storage, and provide a pinned signing identity and independent APK checks. Use DuckDuckGo's official HTML POST form with an honest Novera client identity. Reapply the existing hand icons, match the maintainer's Desktop appearance once after hydration, and suppress mobile status/thread autofocus while retaining manual typing. Keep desktop focus behavior and later appearance choices.

Rename the CLI package, executable, help, command examples, terminal and ACP/MCP/RPC identities to Novera. Recognize canonical environment names while preserving inherited configuration aliases and existing profiles. New ZIPs use identity format 2 and novera.exe/novera. Use latest-novera-cli.json and a v1.0.0-cli-novera release. Replace the promoted CLI links after the new signed packages are verified and available. Historical releases are immutable, so their assets cannot be removed individually and old direct URLs remain accessible; twelve legacy CLI files were backed up with verified digests and none were deleted. Retain Desktop downloads. The initial transition from the old executable is manual because old clients require a jan archive entry.

Update the README, release documentation and Pages presentation with canonical CLI names and the actual Android test status. Publish the new CLI release before deploying links to it. Keep existing Desktop/portable feeds and payloads unchanged. The local Apple-distribution preflight and signature/notarization comparison work is retained, with macOS/iOS follow-up explicitly awaiting Apple access and native/device validation.

Extended Windows tests exposed a pre-existing profile-isolation defect: dirs used the Windows Known Folders API despite the fixture's HOME override. Add a test-only home resolver with a dedicated override, restore environment variables on panic and redirect dependent stores to it; production home resolution remains unchanged. The two newly created fixture files were quarantined, and the pre-existing profile file remained unchanged. Update platform-specific test paths, shell scripts and Git fixture identity, and regenerate the committed protocol schemas rather than weakening their consistency checks.

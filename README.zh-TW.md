## Novera 1.0.1

Novera 1.0.1 適用於下列平台。下載適合您的系統的軟體包或使用其簽署的更新通道。當您安裝新軟體包或接受更新時，現有安裝會更新。

- 安全性：對遠端頁面更嚴格的本機權限、網路 API 和伺服器工具的身份驗證、受保護的秘密儲存和遷移、更安全的檔案/媒體存取、電子表格解析和建置腳本。公開的依賴項已更新；其餘的建議將被公開追蹤。
- 隱私權：統計資訊和錯誤報告需要單獨同意，預設保持關閉狀態。建置包括記錄的目標配置。技術診斷被過濾；使用者可以控制啟動。
- 本機引擎：`llama.cpp v0.9.0` (`b12110`, `cd959bae99ff4bed22bef2604f45241c09bbb8c8`)。引擎版本和應用程式版本是分開的。初始模型設定和模型/投影機註冊已修正，包括涉及 `kv_unified` 的啟動失敗。現有的個人設定將被保留。
- 語言：24 其他語言和變體將介面和翻譯後的 README 集合帶到 104，每個目錄有 2,435 個介面金鑰。此報導並不能證明每種語言的本地編輯品質或語音支援。
- **LFM3-Omni-2B Q4_K_M** — 預設在桌面和行動裝置上。文字、圖像和音訊的緊湊模型，使用所需的 `mmproj` 檔案。下載：兩個檔案大約是 1.39 GB。選擇它以獲得更輕的多模式設定。語音功能取決於平台和引擎。較長的上下文使用更多的記憶體。
- **NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M** — 對話、寫作、工具和結構化答案的純文字替代方案。下載：大約6.18 GB。它需要比 LFM3-Omni 更多的內存，並且本身不處理圖像或音訊。語音回覆使用系統語音。當您有足夠的記憶體時，請選擇它來執行文字任務。透過來源檢查事實答案。

## 從首次發佈到取得成果

**我們的自動化將準備工作與完整的執行工作流程連結。** Novera 處理所選配置可用的技術步驟，同時保持高階控制的可存取性。

| 步驟 | Novera 處理什麼 |
| --- | --- |
| **1。開始** | 在首次啟動時選擇支援的系統語言並儲存您的首選項。提供起始模型和有用的硬體資訊。 |
| **2。準備** | 引導式安裝提供文字、嵌入、圖像、音樂、影片和升級。它會在您批准之前預覽元件、大小和可用空間，然後追蹤下載進度、暫停/恢復和 SHA-256 驗證。 |
| **3。配置** | 註冊模型及其元件，準備相關設定檔並報告所需的依賴關係。檢索嵌入從 CPU 開始，並儲存 CPU/GPU 選擇。新的音樂配置預設為樂器模式。 |
| **4。了解要求** | 自動將辨識的建立請求路由到文字、圖像、音樂或影片。您也可以明確選擇輸出模式以及本機或雲端模型。 |
| **5。執行** | 自動記憶體等待活動工作，釋放不需要的模型並重新載入所需的資源。 1–10 作業系列依序運行，並在下一個作業之前釋放資源。雲端提供者使用選定的帳戶和配置。 |
| **6。檢索和重用** | 將媒體保存在 Novera 系統資料夾中，顯示結果和可用計時，然後提供變體、庫、複製、匯出或系統共用。發送到另一個應用程式仍然是您的操作。 |

自動化涵蓋整合引擎和工作流程；它並不會使每個 Hub 模型都可執行。硬體、安裝的元件和提供者存取權限決定了哪些內容可以運作。資料夾、檔案變更和 shell 指令遵循對話的存取授權。

## 源碼中的功能

| 區域 | 特點 |
| --- | --- |
| **文字和圖像理解** | 對話、文件附件、串流回應以及本地或雲端模型。願景取決於型號；理解和生成圖像是不同的能力。 |
| **圖片** | 對話中產生、種子、比率、解析度、GGUF/Safetensors 元件、設定的 Diffusers 資料夾和支援的本機 NVFP4 CUDA 設定檔。 |
| **音樂** | 本地或雲端生成、持續時間、品質、樂器或人聲（如果支援）、結構化歌詞和音訊播放器。提供者的選擇有所不同。 |
| **視頻** | 本地或雲端生成、持續時間、本地設定檔的幀數/節奏、比率、解析度和視訊播放器。 |
| **搜尋與工具** | Web 搜尋、基於嵌入的文件檢索、MCP、工作區和本機工具（根據模型支援和授予的存取權限）。 |
| **結果與分享** | 媒體庫、變體、回應/對話匯出、文件和原始媒體、列印/PDF 以及依賴平台的系統共用。 |
| **資源管理** | 預設啟用自動內存，支援組件的 CPU/GPU 設置，以及資源允許時的手動設定檔。 |

## 集線器及相容型號

**GGUF、標準和量化 Safetensors、ONNX 和 MLX**：依任務探索模型並選擇與引擎和硬體相容的變體。

| 家人 | 源碼支持 | 要求 |
| --- | --- | --- |
| **GGUF** | 透過llama.cpp產生文字；支援的設定檔的圖像和視訊組件。 | 捆綁引擎識別的架構。 |
| **分離式 GGUF** | 每個完整系列一個變體、總大小、全分片下載和大小/SHA-256/標頭檢查。 | 標準編號檔名；下載 500 GB 並不代表此型號適合此 PC. |
| **標準Safetensors** | 透過 Transformers 完成資料夾，CPU 或 NVIDIA CUDA 上的因果文字。 | 配置、標記器和每個所需的分片。 |
| **ONNX Runtime** | 本地匯入數字/布林圖並準備 GenAI 文字匯出。 | 已驗證的完整資料夾；需要特定於任務的預處理/後處理； [設定與限制](onnx-server/README.md). |
| **LoRA / PEFT 轉接器** | 在 Safetensors 提供者中匯入完整的基礎及其單獨的本機適配器。 | 未量化因果 Transformers 基數、匹配身分、張量檢查和累積記憶體估計； [設定與限制](transformers-server/README.md#local-lora--peft-adapters). |
| **FP8 LLM / ModelOpt** | 原生 CUDA 執行，用於相容於密集 Llama/Qwen2/Qwen3 每個張量 FP8 導出。 | 架構/張量檢查與真實核心探測； [設定與限制](transformers-server/README.md#modelopt-fp8-and-nvfp4-llms). |
| **NVFP4 LLM / ModelOpt** | 打包塊-16 FP4 透過原生 CUDA GEMM 投影；與影像 NVFP4 分開。 | 相容於Blackwell GPU，支援尺寸/導出和實際內核探針；已在 RTX 5070 上使用未訓練的測試模型驗證。 |
| **AWQ** | 4 位元 GEMM 模型檢查點，無操作融合。 | NVIDIA CUDA 和選購的 GPTQModel/Transformers 裝載機。 |
| **GPTQ** | 2/3/4/8 位元配置，gptq/gptq_v2 格式。 | NVIDIA CUDA、GPTQModel 和 Optimum；實際執行在 4 位元進行測試。 |
| **bitsandbytes** | 4 位元 NF4/FP4 或 8 位元 INT8. | NVIDIA CUDA 和可選依賴項；真實的NF4和INT8測試。 |
| **EXL3** | 透過ExLlamaV3加載的完整量化Safetensors模型資料夾；使用 CUDA 的實際生成進行了測試。 | NVIDIA GPU，獨立的Python 3.12環境和相容架構；沒有 CPU 後備。 |
| **EXL2** | 專用ExLlamaV2裝載機；在 GPU. 上進行串流、取消和卸載測試 | 在受測軟體環境中明確選用 CUDA Attention 後端；需要完整的模型檢查點及足夠可用的 VRAM。 |
| **MLX** | Apple Silicon 上的相容型號。 | MLX 引擎及支援平台。 |

集線器現已固定 **LFM3-1.7B** 作為其相容配置的 LiquidAI 推薦，具有 Q4_K_M、Q6_K 和 Q8_0 變體。首次運行的模型仍然是上面指導配置中列出的模型。

過濾下載權重 **1 GB 至 500 GB 以上**，然後依硬體適合度、大小、新近度或下載次數排序。結果逐漸載入；過濾器適用於所取得的模型及其預設變體。記憶體建議使用可用的 RAM/VRAM、上下文和配套元件，而不重複計算共享 GPU 記憶體。

AWQ 4 位元、GPTQ 4 位元、NF4 和 INT8 皆使用離線建立的未經訓練的微型模型在 RTX 5070 Laptop 上產生文字。這驗證了載入和執行，而不是每個模型的品質或效能。 **這些補充在原始碼中：需要重建和相容依賴；此 README 更新不會升級已安裝的二進位。**

**在 RTX 5070 Laptop 上測量：** Qwen2.5-0.5B-Instruct，上下文 2,048，提示 272 令牌，128 產生的令牌，五次預熱運行：中位數解碼 **GGUF Q4_K_M 402.7 tokens/s · EXL3 4 bpw 312.5 · EXL2 4 bpw 146.9**。這裡沒有展示相對於 GGUF 的速度優勢。量化/校準不同，EXL3 未通過一次基礎算術測試；這些結果並不是一般的速度或品質排名。 [完整測量與限制](deliverables/exllama-2026-10-30/validation.md).

**TabbyAPI** 是可選的、單獨管理的 OpenAI 相容伺服器連接，預設為停用。測試了經過身份驗證的 EXL3 模型發現和串流媒體。受管理的本地 ExLlama 路由仍然不同。 [ExLlama 設定與 TabbyAPI 連接](transformers-server/README.md#exl3-first-exl2-second--nvidia-execution).

預設的硬體適應排序有利於相同相容性和可用記憶體層中的較新版本。已安裝的模型不會自動替換。

[量化 Safetensors 設定](transformers-server/README.md#quantized-safetensors--source-integration-29-october-2026) · [格式、優先順序和驗證](docs/SUIVI_MOTEURS.md)

更新的來源添加 **Windows x64 配置中的選用託管元件**：私有Python環境，固定CPU/CUDA設定文件，下載、驗證、修復和刪除之前的估計和確認。自訂解釋器路徑保留在進階選項下。原生 GGUF 引擎保留其現有元件；行動和雲端不下載桌面Python/PyTorch。已使用合成測試資料驗證三個專用 CPU/匯出設定檔；維護者報告 2026年11月1日 成功桌面使用；GPU 設定檔和乾淨的 PC 安裝仍須另行詳細驗證。 [設定檔和測試限制](docs/REPRISE_COMPOSANTS_GERES_80_LANGUES.md)。將堆疊嵌入 EXE 被推遲。

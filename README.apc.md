## Novera 1.0.1

Novera 1.0.1 متاح للأنظمة الأساسية المذكورة أدناه. قم بتنزيل الحزمة لنظامك أو استخدم قناة التحديث الموقعة الخاصة بها. يتم تحديث عمليات التثبيت الموجودة عند تثبيت الحزمة الجديدة أو قبول التحديث.

- الأمان: أذونات أصلية أكثر صرامة للصفحات البعيدة، ومصادقة واجهات برمجة تطبيقات الشبكة وأدوات الخادم، وتخزين وترحيل سري محمي، ووصول أكثر أمانًا إلى الملفات/الوسائط، وتحليل جداول البيانات، وإنشاء البرامج النصية. تم تحديث التبعيات المكشوفة؛ ويتم تتبع التحذيرات المتبقية بشكل علني.
- الخصوصية: تتطلب الإحصائيات وتقارير الأخطاء موافقة منفصلة وتظل معطلة بشكل افتراضي. تتضمن البنيات تكوين الوجهة الموثق. تتم تصفية التشخيص الفني. يحتفظ المستخدمون بالتحكم في التنشيط.
- المحرك المحلي: `llama.cpp v0.9.0` (`b12110`, `cd959bae99ff4bed22bef2604f45241c09bbb8c8`). إصدار المحرك وإصدار التطبيق منفصلان. تم تصحيح إعدادات النموذج الأولية وتسجيل النموذج/جهاز العرض، بما في ذلك فشل بدء التشغيل الذي يتضمن `kv_unified`. يتم الاحتفاظ بالإعدادات الشخصية الموجودة.
- اللغات: 24 لغات ومتغيرات إضافية تعمل على جلب الواجهة ومجموعة README المترجمة إلى 104، مع 2,435 مفاتيح واجهة لكل كتالوج. لا تصادق هذه التغطية على جودة التحرير الأصلية أو دعم الكلام في كل لغة.
- **LFM3-Omni-2B Q4_K_M** — هاد الموديل الافتراضي للكمبيوتر والموبايل. نموذج صغير للنصوص والصور والصوت، يحتاج ملف `mmproj`. حجم تنزيل الملفين نحو 1.39 GB. مناسب لإعداد متعدد الوسائط أخف. ميزات الصوت تعتمد على المنصة والمحرك، والسياق الأطول يحتاج ذاكرة أكبر.
- **NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M** — هاد بديل للنصوص. بديل نصي للمحادثة والكتابة والأدوات والإجابات المنظمة. التنزيل نحو 6.18 GB. يحتاج ذاكرة أكثر من LFM3-Omni ولا يعالج الصور أو الصوت بنفسه. قراءة الإجابات تستعمل صوت النظام. اختاره للمهام النصية إذا كانت الذاكرة كافية، وتحقق من المعلومات بمصادر.
- بالنسبة إلى 1.0.1، فإن LFM3-Omni-2B Q4_K_M مع `mmproj-LFM3-Omni-2B-Q4_K_M.gguf` المطلوب هو التوصية الافتراضية على سطح المكتب والجوال؛ يظل NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M بديلاً للنص فقط. السياق الأولي هو 32,768 من الرموز المميزة على سطح المكتب و2,048 على الهاتف المحمول. تستخدم السياقات الأطول المزيد من الذاكرة. يتم الاحتفاظ باختيارات وإعدادات النموذج الحالي حتى يتم تغييرها بشكل صريح.

## من أول تشغيل لغاية النتائج

**أتمتتنا بتربط التحضير مع سير عمل التنفيذ الكامل.** Novera بيتعامل مع الخطوات التقنية المتاحة للإعداد المختار، مع إبقاء الضوابط المتقدمة متاحة.

| خطوة | شو بيتعامل معو Novera |
| --- | --- |
| **1. ابدأ** | بيختار لغة نظام مدعومة عند أول تشغيل وبيحفظ تفضيلك. بيعرض نماذج بداية ومعلومات هاردوير مفيدة. |
| **2. تجهيز** | التثبيت الموجه بيقدم نصوص، تضمينات، صور، موسيقى، فيديوهات وتكبير. بيعرض المكونات والأحجام والمساحة الفاضية قبل موافقتك، بعدين بيتابع التحميلات مع تقدم، إيقاف/استئناف وتحقق SHA-256. |
| **3. استرجاع وإعادة استخدام** | بيسجّل النماذج ومكوناتها، وبيجهّز البروفايلات والتقارير المتعلقة والمُتطلبات اللازمة. تضمينات الاسترجاع بتبلش على CPU مع اختيار محفوظ CPU/GPU. بروفايلات الموسيقى الجديدة بتصير افتراضياً بالوضع الآلاتي. |
| **4. افهم الطلب** | المحركات والتحقق |
| **5. نفّذ** | الذاكرة التلقائية بتستنى الشغل النشط، بتحرر النماذج اللي ما محتاجة وبتحمّل الموارد المطلوبة من جديد. سلسلة شغل 1–10 بتشتغل بالترتيب وبتحرر الموارد قبل الشغل اللي بعده. مزوّدي الخدمات السحابية بيستخدموا الحساب والإعدادات المختارين. |
| **6. استرجاع وإعادة استخدام** | بيحفظ الوسائط بمجلدات نظام Novera، بيعرض النتائج والأوقات المتاحة، بعدين بيعرض خيارات الأنواع، المكتبة، النسخ، التصدير أو المشاركة بالنظام. الإرسال لتطبيق تاني بضل إجراءك. |

الأتمتة بتشمل المحركات والووركس فلوات المدمجة؛ بس ما بتخلي كل موديل Hub قابل للتنفيذ. الهاردوير، والمكونات المثبتة، ووصول المزود بيحدد شو بيقدر يشتغل. المجلدات، وتغييرات الملفات، وأوامر الشل بتتبع تصاريح الوصول تبع المحادثة.

## المركز والنماذج المتوافقة

**GGUF، و Safetensors القياسي والمكمّم، و ONNX، و MLX**: استكشف النماذج حسب المهمة واختار المتغيرات المتوافقة مع المحرك ومعداتك.

| عائلة | دعم بالمصدر | الإعدادات، والمُجزّئ (tokenizer)، وكل جزء مطلوب. |
| --- | --- | --- |
| **GGUF** | توليد نصوص عبر llama.cpp؛ ومكونات صور وفيديو للملفات المدعومة. | مجلد كامل مُصادق عليه؛ مطلوب معالجة مسبقة/لاحقة خاصة بالمهمة؛ |
| **قسّم GGUF** | نسخة وحدة لكل سلسلة كاملة، الحجم المجموع، تحميل كل الأجزاء، وفحوصات الحجم/SHA-256/الرأس | أسماء ملفات مرقمة قياسية؛ تحميل 500 و GB ما بيعني إنو الموديل مناسب لـ PC. |
| **قياسي Safetensors** | إكمِل المجلدات عن طريق Transformers، النص السببي على CPU أو NVIDIA CUDA. | المتطلبات |
| **ONNX Runtime** | نص عبر GenAI؛ مكونات صور/فيديو للملفات الشخصية المدعومة. | معمارية معترف فيها من قبل المحرك المدمج. [إعداد وقيود](onnx-server/README.md). |
| **محولات LoRA / PEFT** | استورد قاعدة كاملة مع المحوّل المحلي المنفصل تبعها بمزود Safetensors | الأساس Transformers السببي غير المُكمَّم، مطابق للتحقق من الهوية والموترات وتقدير الذاكرة التراكمي؛ [إعداد وقيود](transformers-server/README.md#local-lora--peft-adapters). |
| **FP8 LLM / ModelOpt** | تنفيذ أصلي لـ CUDA للتصديرات المتوافقة لـ Llama/Qwen2/Qwen3 الكثيفة لكل موتر FP8. | تحقق من المعمارية/الموترات ومسبار النواة الحقيقي؛ [إعداد وقيود](transformers-server/README.md#modelopt-fp8-and-nvfp4-llms). |
| **NVFP4 LLM / ModelOpt** | إسقاطات الكتلة المعبأة لـ 16 FP4 عبر عمليات GEMM الأصلية لـ CUDA؛ منفصل عن NVFP4 الخاص بالصورة. | Blackwell GPU متوافق، أبعاد/تصدير مدعومة ومسبار نواة فعلي؛ نماذج اختبار غير مدربة على RTX 5070. |
| **AWQ** | نقاط تفتيش نموذج 4-بت GEMM بدون دمج العمليات. | مُحمّلات NVIDIA CUDA واختيارية GPTQModel/Transformers. |
| **GPTQ** | إعدادات 2/3/4/8-بت، وتنسيقات gptq/gptq_v2. | NVIDIA CUDA، GPTQModel و Optimum؛ اختبار التنفيذ الحقيقي عند بت 4. |
| **bitsandbytes** | NF4/FP4 ببت 4 أو INT8. ببت 8 | NVIDIA CUDA والتبعيات الاختيارية؛ اختبارات NF4 و INT8 حقيقية. |
| **EXL3** | مجلدات نموذج Safetensors الكمّي الكامل محملة عن طريق ExLlamaV3؛ تم اختبار التوليد الفعلي باستخدام CUDA. | NVIDIA GPU، بيئة Python 3.12 منفصلة ومعمارية متوافقة؛ لا يوجد تراجع لـ CPU. |
| **EXL2** | مُحمّل مخصص لـ ExLlamaV2؛ اختبار البث، والإلغاء، والتفريغ على GPU.. | لازم تختار CUDA Attention backend بوضوح للبيئة البرمجية المختبرة؛ مطلوب checkpoint كامل للموديل وذاكرة VRAM متاحة كافية. |
| **MLX** | نماذج متوافقة على Apple Silicon. | محرك MLX والمنصة المدعومة. |

المركز صار يثبّت **LFM3-1.7B** كـ توصية LiquidAI للتكوينات المتوافقة، مع متغيرات Q4_K_M و Q6_K و Q8_0. الموديل تبع أول تشغيل بيضل هو اللي مذكور بالتكوين الموجه فوق.

فلترة أوزان التحميل من **تحت 1 GB لـ 500 GB وفوق**, بعدين رتّب حسب ملاءمة الهاردوير، الحجم، الحداثة أو التحميلات. النتائج بتنزل تدريجياً؛ الفلاتر بتنطبق على الموديلات اللي انحملت ومتغيرها الافتراضي. نصيحة الذاكرة بتستخدم RAM/VRAM المتاح، والسياق والمكونات المرافقة، بدون ما تحسب ذاكرة GPU المشتركة مرتين.

AWQ 4-bit، GPTQ 4-bit، NF4 و INT8 كل واحد منهم ولّد نص على RTX 5070 Laptop باستخدام موديلات صغيرة غير مدربة انعملت أوفلاين. هاد بيأكد التحميل والتنفيذ، مو جودة أو أداء كل موديل. **هالإضافات موجودة بالمصدر: مطلوب إعادة بناء واعتماديات متوافقة؛ تحديث README هاد ما بيرقي أي باينري مُثبّت.**

**مقاس على RTX 5070 Laptop:** Qwen2.5-0.5B-Instruct، سياق 2,048، توكنات البرومبت 272، توكنات مُولّدة 128، خمس تشغيلات مُدفّاة: وسيط سرعة توليد التوكنات **GGUF Q4_K_M 402.7 tokens/s · EXL3 4 bpw 312.5 · EXL2 4 bpw 146.9**. ما انعرض أي فائدة بالسرعة مقارنة بـ GGUF هون. التكميم/المعايرة مختلف، و EXL3 فشل باختبار حساب بسيط واحد؛ هدول النتائج مو تصنيف عام للسرعة أو الجودة. [القياسات والحدود الكاملة](deliverables/exllama-2026-10-30/validation.md).

**TabbyAPI** هو اتصال سيرفر اختياري ومُدار بشكل منفصل ومتوافق مع OpenAI، ومُعطّل بشكل افتراضي. تم اختبار اكتشاف وتدفق موديل EXL3 الموثّق. المسار المحلي المُدار ExLlama بيضل مميز. [إعداد ExLlama واتصال TabbyAPI](transformers-server/README.md#exl3-first-exl2-second--nvidia-execution).

الترتيب الافتراضي المُكيّف مع الهاردوير بيفضّل الإصدارات الأحدث بنفس مستوى التوافق والذاكرة المتاحة. الموديلات المثبتة ما بتنستبدل تلقائياً.

[إعداد Safetensors المُكمّم](transformers-server/README.md#quantized-safetensors--source-integration-29-october-2026) · [التنسيقات، الأولويات، والتحقق](docs/SUIVI_MOTEURS.md)

المصادر المُحدّثة بتضيف **مكونات مُدارة اختيارية بالإعدادات لـ Windows x64**: بيئات بايثون خاصة، ملفات تعريف CPU/CUDA مثبتة، تقديرات وتأكيد قبل التحميل، تحقق، إصلاح وإزالة. مسارات المفسر المخصصة بتضل تحت الخيارات المتقدمة. محركات GGUF الأصلية بتحافظ على مكوناتها الموجودة؛ الموبايل والسحابة ما بيحملوا بايثون ديسكتوب/PyTorch. تم اختبار ثلاث ملفات تعريف خاصة CPU/تصدير ببيانات اختبار اصطناعية؛ المسؤول عن صيانة المشروع بيبلّغ عن استخدام ناجح على الديسكتوب بـ 1 تشرين الثاني 2026؛ ملفات تعريف GPU وتثبيت clean-PC لسا بدها تحقق منفصل ومفصّل. [ملفات التعريف وحدود الاختبار](docs/REPRISE_COMPOSANTS_GERES_80_LANGUES.md). تضمين الحزمة بـ EXE مؤجّل.

| النقل، اللوجستيات، السياحة، الرياضة وحياة المجتمع | مساعدة بالتخطيط، التواصل، التعلم والمبادرات المحلية. |

هاي توجيهات للمساهمة والتطوير، مو ادعاء إنو كل تطبيق خاص بقطاع معين تم تسليمه أو توثيقه. بدنا توجيه بسيط للاستخدام اليومي، خيارات متقدمة واضحة لما نحتاجها، متطلبات شفافة للأجهزة والسحابة، وتعاون مع الناس اللي بيعرفوا كل مجال والسياق المحلي.

## حالة المشروع

لقطة الشاشة بتورجي تطبيق Windows مجمّع محلياً من قبل المُحافظ. تغييرات المصدر، الاختبارات المستهدفة وتوثيق الأجهزة بتنكتب بشكل منفصل؛ هاد ما بيوثق كل نموذج، منصة أو حساب سحابي.

تجميعات GitHub Actions اليدوية مُفعلة لكل أحد عشر نوع توزيع. تابع [نتائج التجميع وتنزيلات المرشحين الموثّقين](docs/CI_DISTRIBUTIONS.md); التوافر مُسجّل بشكل منفصل لكل منصة. المرشحين مختلفين عن الإصدارات الإنتاجية الموقّعة. متطلبات التوزيع موصوفة في الـ [سياسة الإصدار الرسمية](OFFICIAL_RELEASES.md) و [صفحة الإصدارات](https://github.com/TRON-ABS/Novera/releases)باقي المرشحين اللي معطلين التحديث بيضلوا داخليين. الإصدارات العامة بتحتاج آلية تحديث مُهيأة ومُوثّقة؛ [فحوصات التوقيع على سطح المكتب ومتطلبات التشغيل المتبقية موثقة](docs/LAUNCH_STATUS.md).

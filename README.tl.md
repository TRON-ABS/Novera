## Novera 1.0.1

Novera 1.0.1 ay available para sa mga platform na nakalista sa ibaba. I-download ang package para sa iyong system o gamitin ang nilagdaang update channel nito. Ang mga kasalukuyang pag-install ay na-update kapag nag-install ka ng bagong package o tinanggap ang update.

- Seguridad: mas mahigpit na mga native na pahintulot para sa malalayong pahina, pagpapatotoo para sa mga network API at mga tool sa server, protektadong sikretong storage at paglipat, mas ligtas na pag-access sa file/media, pag-parse ng spreadsheet at pagbuo ng mga script. Na-update ang mga nakalantad na dependency; ang natitirang mga advisory ay bukas na sinusubaybayan.
- Privacy: ang mga istatistika at ulat ng error ay nangangailangan ng hiwalay na pahintulot at nananatiling naka-off bilang default. Kasama sa mga Build ang nakadokumentong configuration ng destinasyon. Sinasala ang mga teknikal na diagnostic; pinapanatili ng mga gumagamit ang kontrol sa pag-activate.
- Lokal na makina: `llama.cpp v0.9.0` (`b12110`, `cd959bae99ff4bed22bef2604f45241c09bbb8c8`). Ang bersyon ng engine at bersyon ng application ay magkahiwalay. Ang mga setting ng paunang modelo at pagpaparehistro ng modelo/projector ay naitama, kabilang ang pagkabigo sa pagsisimula na kinasasangkutan ng `kv_unified`. Ang mga kasalukuyang personal na setting ay pinapanatili.
- Mga Wika: 24 na mga karagdagang wika at variant ang nagdadala ng interface at isinalin na koleksyon ng README sa 104, na may 2,435 mga interface key bawat catalog. Ang saklaw na ito ay hindi nagpapatunay ng katutubong kalidad ng editoryal o suporta sa pagsasalita sa bawat wika.

I-download: tungkol sa 1.39 GB para sa parehong mga file. Piliin ito para sa mas magaan na multimodal na setup. Ang mga feature ng boses ay nakadepende sa platform at engine. Ang mas mahabang konteksto ay gumagamit ng mas maraming memorya.
- **NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M** — Text-only na alternatibo para sa pag-uusap, pagsulat, mga tool at mga structured na sagot. I-download: tungkol sa 6.18 GB. Nangangailangan ito ng higit pang memory kaysa sa LFM3-Omni at hindi nagpoproseso ng mga larawan o audio mismo. Ginagamit ng mga pasalitang tugon ang boses ng system. Piliin ito para sa mga gawaing teksto kapag mayroon kang sapat na memorya. Suriin ang mga makatotohanang sagot gamit ang mga mapagkukunan.

Ang mga kasalukuyang pagpipilian at setting ng modelo ay pinapanatili hanggang sa tahasang baguhin.
- Boses: direktang lokal na input ng mikropono para sa LFM3-Omni, tuluy-tuloy na pag-uusap at awtomatikong pagpapadala, mga boses ng lalaki/babae sa pagtugon para sa mga audio model, at system speech para sa mga classic na modelo. | **1. Magsimula** | Pumili ng sinusuportahang wika ng system sa unang paglunsad at sine-save ang iyong kagustuhan. Nagpapakita ng mga panimulang modelo at kapaki-pakinabang na impormasyon ng hardware. |
| **2. Maghanda** | Nag-aalok ang may gabay na pag-install ng text, mga pag-embed, larawan, musika, video at pag-upscale. Ito ay nagpi-preview ng mga bahagi, laki at libreng espasyo bago ang iyong pag-apruba, pagkatapos ay sinusubaybayan ang mga pag-download na may pag-usad, i-pause/ipagpatuloy at SHA-256 na pag-verify. |
| **3. I-configure** | Nagrerehistro ng mga modelo at mga bahagi ng mga ito, naghahanda ng mga nauugnay na profile at nag-uulat ng mga kinakailangang dependency. Magsisimula ang mga retrieval embeddings sa CPU na may naka-save na CPU/GPU na pagpipilian. Ang mga bagong profile ng musika ay default sa instrumental mode. |
| **4. Intindihin ang kahilingan** | Kinikilala ng mga awtomatikong ruta ang mga kahilingan sa paggawa sa text, larawan, musika o video. Maaari mo ring tahasang piliin ang output mode at isang lokal o cloud model. |
| **5. Ipatupad** | Ang awtomatikong memorya ay naghihintay para sa aktibong gawain, naglalabas ng mga hindi kinakailangang modelo at nagre-reload ng mga kinakailangang mapagkukunan. Ang isang 1–10 na serye ng trabaho ay tumatakbo nang maayos at naglalabas ng mga mapagkukunan bago ang susunod na trabaho. Ginagamit ng mga cloud provider ang napiling account at configuration. |
| **6. Kunin at muling gamitin** | Nagse-save ng media sa mga folder ng system ng Novera, nagpapakita ng mga resulta at mga available na timing, pagkatapos ay nag-aalok ng mga variant, ang library, pagkopya, pag-export o pagbabahagi ng system. Ang pagpapadala sa ibang application ay nananatiling iyong aksyon. |

Sinasaklaw ng automation ang mga pinagsama-samang makina at daloy ng trabaho; hindi nito ginagawang executable ang bawat modelo ng Hub. Tinutukoy ng hardware, naka-install na mga bahagi at access ng provider kung ano ang maaaring tumakbo. Ang mga folder, pagbabago ng file at shell command ay sumusunod sa mga pagbibigay ng access sa pag-uusap.

## Mga kakayahan sa pinagmulan

| Lugar | Mga Tampok |
| --- | --- |

| **Mga resulta at pagbabahagi** | Media library, mga variant, pag-export ng tugon/pag-uusap, mga dokumento at orihinal na media, pag-print/PDF at pagbabahagi ng system na umaasa sa platform. |
| **Pamamahala ng mapagkukunan** | Naka-enable ang awtomatikong memory bilang default, mga setting ng CPU/GPU para sa mga sinusuportahang bahagi at manu-manong profile kapag pinapayagan ang mga mapagkukunan. |

## Hub at mga katugmang modelo

**GGUF, standard at quantized Safetensors, ONNX, at MLX**: galugarin ang mga modelo ayon sa gawain at pumili ng mga variant na tugma sa makina at sa iyong hardware.

| Pamilya | Suporta sa pinagmulan | Mga Kinakailangan |
| --- | --- | --- |
| **GGUF** | Pagbuo ng teksto sa pamamagitan ng llama.cpp; mga bahagi ng larawan at video para sa mga sinusuportahang profile. | Arkitektura na kinikilala ng naka-bundle na makina. |
| **Hatiin ang GGUF** | Isang variant bawat kumpletong serye, summed size, all-shard download at size/SHA-256/header checks. | Mga karaniwang numerong filename; ang pag-download ng 500 GB ay hindi nangangahulugan na ang modelo ay akma sa PC. na ito |
| **Karaniwang Safetensors** | Kumpletuhin ang mga folder sa pamamagitan ng Transformers, causal text sa CPU o NVIDIA CUDA. | Configuration, tokenizer at bawat kinakailangang shard. |
| **ONNX Runtime** | Lokal na pag-import ng mga numeric/bool graph at inihandang GenAI na mga export ng text. | Na-validate ang kumpletong folder; kinakailangan ang preprocessing/postprocessing na tukoy sa gawain; [setup at limitasyon](onnx-server/README.md). |
| **LoRA / PEFT adapter** | Mag-import ng kumpletong base kasama ang hiwalay na lokal na adapter nito sa Safetensors provider. | Di-quantized na sanhi ng Transformers base, pagtutugma ng pagkakakilanlan, tensor check at pinagsama-samang pagtatantya ng memorya; [setup at limitasyon](transformers-server/README.md#local-lora--peft-adapters). |
| **FP8 LLM / ModelOpt** | Native CUDA execution para sa compatible na siksik na Llama/Qwen2/Qwen3 per-tensor FP8 export. | Mga pagsusuri sa arkitektura/tensor at totoong kernel probe; [setup at limitasyon](transformers-server/README.md#modelopt-fp8-and-nvfp4-llms). |
| **NVFP4 LLM / ModelOpt** | Naka-pack na block-16 FP4 projection sa pamamagitan ng mga katutubong CUDA GEMM; hiwalay sa larawan NVFP4. | Mga katugmang Blackwell GPU, mga sinusuportahang dimensyon/export at aktwal na kernel probe; mga modelong pangsubok na hindi pa sinanay na sinubukan sa RTX 5070. |
| **AWQ** | 4-bit na GEMM na mga checkpoint ng modelo nang walang operation fusion. | NVIDIA CUDA at opsyonal na GPTQModel/Transformers loader. |
| **GPTQ** | 2/3/4/8-bit na mga configuration, gptq/gptq_v2 na mga format. | NVIDIA CUDA, GPTQModel at Optimum; nasubok ang tunay na pagpapatupad sa 4 bits. |
| **bitsandbytes** | 4-bit NF4/FP4 o 8-bit INT8. | NVIDIA CUDA at mga opsyonal na dependency; tunay na NF4 at INT8 na mga pagsubok. |
| **EXL3** | Kumpletuhin ang quantized Safetensors na mga folder ng modelo na na-load sa pamamagitan ng ExLlamaV3; ang aktwal na henerasyon na may CUDA ay sinubukan. | NVIDIA GPU, hiwalay na Python 3.12 na kapaligiran at katugmang arkitektura; walang CPU fallback. |
| **EXL2** | Nakatuon na ExLlamaV2 loader; nasubok ang streaming, pagkansela at pag-unload sa GPU. | CUDA Attention backend ay dapat na tahasang piliin para sa nasubok na stack ng software; isang kumpletong checkpoint ng modelo at available na VRAM ay kinakailangan. |
| **MLX** | Mga katugmang modelo sa Apple Silicon. | MLX engine at suportadong platform. |

Naka-pin na ngayon ang Hub **LFM3-1.7B** bilang rekomendasyon nitong LiquidAI para sa mga katugmang configuration, na may mga variant ng Q4_K_M, Q6_K at Q8_0. Ang unang pinatakbo na modelo ay nananatiling nakalista sa ginabayang configuration sa itaas.

I-filter ang mga timbang sa pag-download mula sa **sa ilalim ng 1 GB hanggang 500 GB at mas mataas**, pagkatapos ay pagbukud-bukurin ayon sa hardware fit, laki, kabago-bago o pag-download. Progresibong naglo-load ang mga resulta; nalalapat ang mga filter sa mga kinuhang modelo at ang kanilang default na variant. Ang payo sa memorya ay gumagamit ng magagamit na RAM/VRAM, konteksto at mga kasamang bahagi, nang walang dobleng pagbibilang ng nakabahaging GPU na memorya.

AWQ 4-bit, GPTQ 4-bit, NF4 at INT8 bawat isa ay nakabuo ng text sa isang RTX 5070 Laptop gamit ang maliliit na hindi sinanay na mga modelo na ginawa offline. Pinapatunayan nito ang paglo-load at pagpapatupad, hindi ang kalidad o pagganap ng bawat modelo. **Ang mga karagdagan na ito ay nasa pinagmulan: kailangan ang muling pagtatayo at mga katugmang dependency; ang README update na ito ay hindi nag-a-upgrade ng naka-install na binary.**

**Sinukat sa RTX 5070 Laptop:** Qwen2.5-0.5B-Instruct, konteksto 2,048, prompt 272 token, 128 na nabuong mga token, limang warmed run: median decode **GGUF Q4_K_M 402.7 tokens/s · EXL3 4 bpw 312.5 · EXL2 4 bpw 146.9**. Walang pakinabang sa bilis sa GGUF ang ipinakita dito. Naiiba ang quantization/calibration, at nabigo ang EXL3 sa isang simpleng pagsusulit sa aritmetika; ang mga resultang ito ay hindi pangkalahatang bilis o pagraranggo ng kalidad. [Buong mga sukat at limitasyon](deliverables/exllama-2026-10-30/validation.md).

**TabbyAPI** ay isang opsyonal, hiwalay na pinamamahalaan ang OpenAI-compatible na koneksyon sa server, na hindi pinagana bilang default. Sinubukan ang napatunayang pagtuklas at streaming ng modelong EXL3. Ang pinamamahalaang lokal na rutang ExLlama ay nananatiling naiiba. [ExLlama setup at TabbyAPI na koneksyon](transformers-server/README.md#exl3-first-exl2-second--nvidia-execution).

Ang default na hardware-adapted sort ay pinapaboran ang mga bagong release sa loob ng parehong compatibility at available-memory tier. Ang mga naka-install na modelo ay hindi awtomatikong pinapalitan.

[Quantized Safetensors setup](transformers-server/README.md#quantized-safetensors--source-integration-29-october-2026) · [Mga format, priyoridad at pagpapatunay](docs/SUIVI_MOTEURS.md)

Idinagdag ang Nagdagdag ang na-update na source code ng **opsyonal na pinamamahalaang mga bahagi sa Configurations para sa Windows x64**: mga pribadong Python environment, naka-pin na CPU/CUDA na mga profile, mga pagtatantya at kumpirmasyon bago ang mga pag-download, pag-verify, pagkumpuni at pagtanggal. Ang mga custom na interpreter path ay nananatili sa ilalim ng mga advanced na opsyon. Pinapanatili ng mga katutubong GGUF na makina ang kanilang mga kasalukuyang bahagi; ang mobile at cloud ay hindi nagda-download ng desktop Python/PyTorch. Tatlong pribadong CPU/export na profile ang ginamit gamit ang sintetikong datos para sa pagsubok; Iniuulat ng maintainer ang matagumpay na paggamit ng desktop sa 1 Nobyembre 2026; Ang mga profile ng GPU at ang pag-install ng clean-PC ay nangangailangan pa rin ng hiwalay, detalyadong pagpapatunay. [Mga profile at limitasyon sa pagsubok](docs/REPRISE_COMPOSANTS_GERES_80_LANGUES.md). Ang pag-embed ng stack sa EXE ay ipinagpaliban.

## لوحة تحكم واحدة لكل حاجة بتعملها

Novera بيكبر معاك. أمثلتك وإعداداتك ممكن تساعد مستخدمين تانيين يلاقوا إعداد مناسب. شارك أسئلة، مشاكل وأفكار على [صفحة Facebook](https://www.facebook.com/profile.php?id=61596114515071) أو عن طريق [إيميل](mailto:contact.novera.tronabs@gmail.com). لو ينفع، حط إصدار Novera بتاعك، الجهاز والموديل المحلي/API. شيل أي معلومات شخصية وماتشاركش مفاتيح أو كلمات مرور API أبداً.

![صورة مولّدة من Novera ولوحة تحكم موحدة فيها الكمية، والبذرة، وتكبير الصورة، والذاكرة الأوتوماتيكية](.github/assets/novera-dashboard-2026-11-01.png)

*لقطة شاشة حقيقية لتطبيق Windows قدمها المسؤول عن صيانة المشروع في 1 شهر نوفمبر 2026، وبيقول إن التطبيق شغال كويس. بتورّي منظر طبيعي مولّد، وضبط ملفات محفوظة، ولوحة تحكم موحدة للإبداع؛ دي مش مجرد نموذج وهمي.*

لوحة واحدة، وخمس أوضاع: **تلقائي / نص / الصورة / موسيقى / فيديو**. الضبط بيتبع الوضع اللي اخترته: نسبة، دقة، مدة، إيقاع، جودة، آلات، كلمات، بذرة، وكمية.

- **توليدات متتابعة من 1–10**, وبيعتمد على 1 بشكل افتراضي، بكميات مستقلة للصورة والموسيقى والفيديو. إيقاف بيلغي المهمة النشطة والصف الانتظار الباقي.
- **عشوائية، ثابتة، +1 و −1 بذرات.**, نسب مُحددة مسبقاً أو مُخصصة واختياري **Real-ESRGAN ×2/×4** تكبير الصورة مع عرض الأبعاد النهائية.
- النموذج اللي اخترته، والذاكرة الأوتوماتيكية، والمرفقات، والتعليمات، والبحث على الويب والأدوات بتفضل في نفس الشريط. الأدوات بتعتمد على قدرات النموذج والصلاحيات المعطاة.

## من أول تشغيل لحد النتائج.

**الأتمتة بتاعتنا بتربط التجهيز بشغل التنفيذ الكامل.** Novera بيتعامل مع الخطوات التقنية المتاحة للإعداد اللي اخترته، وفي نفس الوقت بيخلي الضبط المتقدم متاح.

| خطوة | إيه اللي بيتعامل معاه Novera |
| --- | --- |
| **1. ابدأ** | بيختار لغة نظام مدعومة أول ما يتشغّل وبيحفظ اختيارك. بيعرض نماذج بداية ومعلومات مفيدة عن الهاردوير. |
| **2. تجهيز** | التنصيب الموجه بيقدّم نصوص، تضمينات، صور، موسيقى، فيديوهات وتكبير. بيعرض المكونات والأحجام والمساحة الفاضية قبل موافقتك، وبعدين بيتابع التحميلات بالتقدم، إيقاف/استئناف، ومصادقة SHA-256. |
| **3. استرجاع وإعادة استخدام** | بيسجّل الموديلات ومكوناتها، وبيجهّز البروفايلات والتقارير اللازمة للمتطلبات. التضمينات الاسترجاعية بتبدأ على CPU مع اختيار محفوظ CPU/GPU. بروفايلات المزيكا الجديدة بتكون افتراضياً في وضع الآلات الموسيقية. |
| **4. افهم الطلب** | المحركات والتحقق |
| **5. تنفّذ** | الذاكرة الأوتوماتيكية مستنية الشغل النشط، بتفضي الموديلات اللي مش محتاجينها وبتعيد تحميل الموارد المطلوبة. سلسلة شغل 1–10 بتشتغل بالترتيب وبتفضي الموارد قبل الشغل اللي جاي. مزودي الخدمات السحابية بيستخدموا الحساب والإعدادات اللي مختارينه. |
| **6. استرجاع وإعادة استخدام** | بيحفظ الميديا في مجلدات نظام Novera، بيورّي النتائج والمواعيد المتاحة، وبعدين بيعرض المتغيرات، والمكتبة، والنسخ، والتصدير، أو المشاركة بالنظام. الإرسال لتطبيق تاني بيبقى قرارك أنت. |

الأتمتة بتغطي المحركات وسير العمل المتكاملة؛ مش بتخلي كل موديل Hub قابل للتنفيذ. الهاردوير، المكونات المثبتة، ووصول المزود هما اللي بيحددوا إيه اللي ممكن يشتغل. المجلدات، تغييرات الملفات، وأوامر الشيل بتتبع تصاريح الوصول بتاعة المحادثة.

[دليل المستخدم](docs/USER_GUIDE.md) · [محركات والتحقق](docs/SUIVI_MOTEURS.md) · [بيوجّه طلبات الإنشاء المعترف بيها أوتوماتيك للنص، الصورة، المزيكا أو الفيديو. ممكن كمان تختار وضع الإخراج وموديل محلي أو سحابي بشكل واضح.](docs/DEVELOPMENT.md)

في المصادر المُحدّثة، **الإعدادات بتظبّط توصياتها للموبايل وللأجهزة اللي مواردها محدودة**LFM3-1.7B Q4، أو LFM3-Omni-2B Q4 مع البروجيكتور بتاعه لما متطلبات الميموري والموتور اللي اتقالت تتنفذ. التوليد المحلي اللي مش متاح بيكون مستخبي أو محظور؛ الصورة والمزيكا والفيديو السحابي اللي متظبطين بيفضلوا متاحين. إرشاد الواجهة بيستخدم كتالوجات لغة 80. التقديرات دي لسه محتاجة اختبار الجهاز وإعادة بناء عشان توصل للتطبيقات المثبتة.

| **مُكيّفات (adapters) LoRA / PEFT** | استورد قاعدة كاملة مع المُكيّف المحلي المنفصل بتاعها في مُزوّد Safetensors. | الأساس Transformers السببي غير المُكمّم، بيطابق الهوية، فحص التنسور، وتقدير الذاكرة التراكمي؛ [الإعدادات والحدود](transformers-server/README.md#local-lora--peft-adapters). |
| **FP8 LLM / ModelOpt** | تنفيذ أصلي لـ CUDA للتصديرات FP8 لكل تنسور Llama/Qwen2/Qwen3 الكثيفة المتوافقة. | فحص المعمارية/التنسور واستقصاء النواة الحقيقي؛ [الإعدادات والحدود](transformers-server/README.md#modelopt-fp8-and-nvfp4-llms). |
| **NVFP4 LLM / ModelOpt** | إسقاطات الكتلة المعبأة 16 FP4 عن طريق GEMMs الأصلية CUDA؛ منفصل عن صورة NVFP4. | Blackwell GPU متوافقة، أبعاد/تصدير مدعومة واستقصاء نواة حقيقي؛ نماذج اختبار غير مدربة اتختبرت على RTX 5070. |
| **AWQ** | نقاط تفتيش نموذج GEMM بحجم 4-bit من غير دمج عمليات. | مُحمّلات NVIDIA CUDA واختياري GPTQModel/Transformers. |
| **GPTQ** | إعدادات 2/3/4/8-بت، صيغ gptq/gptq_v2. | NVIDIA CUDA، GPTQModel و Optimum؛ تنفيذ حقيقي اتختبر على بت 4. |
| **bitsandbytes** | 4-بت NF4/FP4 أو 8-بت INT8. | NVIDIA CUDA واعتمادات اختيارية؛ اختبارات NF4 و INT8 حقيقية. |
| **EXL3** | مجلدات نموذج Safetensors الكمّي الكامل اتحمّل عن طريق ExLlamaV3؛ التجنيز الفعلي مع CUDA اتختبر. | NVIDIA GPU، بيئة Python 3.12 منفصلة ومعمارية متوافقة؛ مفيش رجوع لـ CPU. |
| **EXL2** | مُحمّل مخصص لـ ExLlamaV2؛ بث، إلغاء وتحميل اتختبروا على GPU.. | لازم تختار CUDA Attention backend بوضوح للبيئة البرمجية المختبرة؛ مطلوب checkpoint كامل للموديل وذاكرة VRAM متاحة كافية. |
| **MLX** | نماذج متوافقة على Apple Silicon. | محرك MLX والمنصة المدعومة. |

الهب دلوقتي بيثبّت **LFM3-1.7B** زي توصية LiquidAI للتكوينات المتوافقة، مع أنواع Q4_K_M و Q6_K و Q8_0. الموديل بتاع أول تشغيل يفضل اللي مكتوب في التكوين الموجه فوق.

صَفّي أوزان التحميل من **تحت 1 GB لـ 500 GB وفوق**, بعدين رتّب حسب توافق الهاردوير، الحجم، الحداثة، أو التحميلات. النتائج بتتحمّل تدريجياً؛ الفلاتر بتنطبق على الموديلات اللي اتحمّلت ونوعها الافتراضي. نصيحة الذاكرة بتستخدم RAM/VRAM المتاح، السياق، والمكونات المرافقة، من غير ما تحسب ذاكرة GPU المشتركة مرتين.

AWQ 4-bit، GPTQ 4-bit، NF4 و INT8 كل واحد عمل نصوص على RTX 5070 Laptop باستخدام موديلات صغيرة مش مدربة اتعملت بره النت. ده بيأكد التحميل والتنفيذ، مش جودة أو أداء كل موديل. **الإضافات دي موجودة في المصدر: محتاج إعادة بناء واعتماديات متوافقة؛ تحديث README ده مش بيحدّث ملف ثنائي مُثبّت.**

**مُقاس على RTX 5070 Laptop:** Qwen2.5-0.5B-Instruct، سياق 2,048، توكنات البرومبت 272، توكنات مُولّدة 128، خمس تشغيلات مُدفّاة: وسيط سرعة توليد التوكنات **GGUF Q4_K_M 402.7 tokens/s · EXL3 4 bpw 312.5 · EXL2 4 bpw 146.9**. مفيش فايدة في السرعة فوق GGUF اتأكدت هنا. الكمّيّة/المعايرة مختلفة، و EXL3 فشل في برومبت واحد حسابي؛ النتائج دي مش ترتيب عام للسرعة أو الجودة. [القياسات والحدود الكاملة](deliverables/exllama-2026-10-30/validation.md).

**TabbyAPI** هو وصلة سيرفر اختيارية ومُدارة لوحدها ومتوافقة مع OpenAI، ومقفولة افتراضياً. تم اختبار اكتشاف وتدفق موديل EXL3 الموثق. المسار المحلي المُدار ExLlama لسه مختلف. [تجهيز ExLlama ووصلة TabbyAPI](transformers-server/README.md#exl3-first-exl2-second--nvidia-execution).

الترتيب الافتراضي المتكيف مع الهاردوير بيفضّل الإصدارات الأحدث في نفس مستوى التوافق والذاكرة المتاحة. الموديلات المثبتة مش بتتغير لوحدها.

[تجهيز Safetensors المُكمَّم](transformers-server/README.md#quantized-safetensors--source-integration-29-october-2026) · [التنسيقات، الأولويات، والتأكيد](docs/SUIVI_MOTEURS.md)

المصادر المُحدّثة بتضيف **مكونات مُدارة اختيارية في الإعدادات لـ Windows x64**: بيئات بايثون خاصة، ملفات تعريف CPU/CUDA مثبتة، تقديرات وتأكيد قبل التحميل، تحقق، إصلاح وإزالة. مسارات المفسر المخصصة بتفضل تحت الخيارات المتقدمة. محركات GGUF الأصلية بتحافظ على مكوناتها الموجودة؛ الموبايل والسحابة مابتحمّلش بايثون ديسكتوب/PyTorch. تم تجربة ثلاث ملفات تعريف خاصة CPU/تصدير ببيانات اختبار اصطناعية؛ المسؤول عن صيانة المشروع بيبلغ عن استخدام ناجح على الديسكتوب في 1 نوفمبر 2026؛ ملفات تعريف GPU وتثبيت clean-PC لسه محتاجين تحقق منفصل ومفصل. [ملفات التعريف وحدود الاختبار](docs/REPRISE_COMPOSANTS_GERES_80_LANGUES.md). تضمين الحزمة في EXE مؤجّل.

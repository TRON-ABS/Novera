## Novera 1.0.1

Novera 1.0.1 适用于下列平台。下载适合您的系统的软件包或使用其签名的更新通道。当您安装新软件包或接受更新时，现有安装会更新。

- 安全性：对远程页面更严格的本机权限、网络 API 和服务器工具的身份验证、受保护的秘密存储和迁移、更安全的文件/媒体访问、电子表格解析和构建脚本。公开的依赖项已更新；其余的建议将被公开追踪。
- 隐私：统计信息和错误报告需要单独同意，默认情况下保持关闭状态。构建包括记录的目标配置。技术诊断被过滤；用户可以控制激活。
- 本地引擎：`llama.cpp v0.9.0` (`b12110`, `cd959bae99ff4bed22bef2604f45241c09bbb8c8`)。引擎版本和应用程序版本是分开的。初始模型设置和模型/投影仪注册已得到纠正，包括涉及 `kv_unified` 的启动失败。现有的个人设置将被保留。
- 语言：24 其他语言和变体将界面和翻译后的 README 集合带到 104，每个目录有 2,435 个界面密钥。此报道并不能证明每种语言的本地编辑质量或语音支持。
- **LFM3-Omni-2B Q4_K_M** — 默认在桌面和移动设备上。文本、图像和音频的紧凑模型，使用所需的 `mmproj` 文件。下载：两个文件大约为 1.39 GB。选择它以获得更轻的多模式设置。语音功能取决于平台和引擎。较长的上下文使用更多的内存。
- **NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M** — 对话、写作、工具和结构化答案的纯文本替代方案。下载：大约6.18 GB。它需要比 LFM3-Omni 更多的内存，并且本身不处理图像或音频。语音回复使用系统语音。当您有足够的内存时，请选择它来执行文本任务。通过来源检查事实答案。
- 对于 1.0.1，LFM3-Omni-2B Q4_K_M 及其必需的 `mmproj-LFM3-Omni-2B-Q4_K_M.gguf` 是桌面和移动设备上的默认建议； NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M 仍然是纯文本替代方案。桌面上的初始上下文是 32,768 令牌，移动设备上的初始上下文是 2,048。较长的上下文使用更多的内存。现有的模型选择和设置将被保留，直到明确更改为止。
- 语音：LFM3-Omni直接本地麦克风输入，连续对话和自动发送，音频模型有男/女回复声音，经典模型有系统语音。回复阅读也适用于键入的消息和重新生成，与麦克风捕获无关。一个小声音按钮可以启用或静音阅读。
- 麦克风状态：绿色表示可用，红色表示忙碌，灰色表示不可用。识别、听力重新启动、焦点处理和可见听写均已得到纠正。原生音频模型语音目前在 Windows 上实现；其他平台仍然需要本机验证和合适的语音支持。
- 网络：更可靠的天气请求检测、当前日期指南、最新结果和引用，以及工具使用后以当前请求为中心的答案。语音省略了装饰性来源标签和链接，同时保留可见的引用。只要所选模型支持，响应和语音语言就会遵循用户的语言。
- 优化：启用互联网时在后台准备网络搜索、共享服务启动、在播放前准备下一个语音片段并提高句子的连续性。法国年份、十进制数字和单位读起来更自然。网络延迟和模型速度仍然取决于设置。
- 舒适：下部控件折叠，同时输入保持可见。紧凑的麦克风和披露控件、麦克风下方的声音按钮、响应式音乐设置和翻译的组件标签改善了小屏幕上的使用。
- API 目录：43 提供商资料，包括本地的 TabbyAPI，以及更新的聊天和媒体选择。新条目包括受支持的 GPT-6.1 Terra, Kimi K3.1 Pro, MiniMax M3.1 Flash, GLM 5.3 Flash, Hy4 和 GPT Image 2.6, Gemini Omni 1.2, FLUX 3。刷新不再隐藏超过十个模型的结果。尊重准确的标识符、区域端点、私有部署和导入的模型。
- 验证：目标应用程序、本机库、公共目录和语言检查记录在详细注释中。该界面是为 Windows / macOS / Linux / Android / iOS 构建的。这些前端构建并不验证每个设备上的本机包或推理。

## 从首次发布到取得成果

**我们的自动化将准备工作与完整的执行工作流程连接起来。** Novera 处理所选配置可用的技术步骤，同时保持高级控件的可访问性。

| 步骤 | Novera 处理什么 |
| --- | --- |
| **1。开始** | 在首次启动时选择支持的系统语言并保存您的首选项。提供起始模型和有用的硬件信息。 |
| **2。准备** | 引导式安装提供文本、嵌入、图像、音乐、视频和升级。它会在您批准之前预览组件、大小和可用空间，然后跟踪下载进度、暂停/恢复和 SHA-256 验证。 |
| **3。配置** | 注册模型及其组件，准备相关配置文件并报告所需的依赖关系。检索嵌入从 CPU 开始，并保存 CPU/GPU 选择。新的音乐配置文件默认为乐器模式。 |
| **4。了解要求** | 自动将识别的创建请求路由到文本、图像、音乐或视频。您还可以显式选择输出模式以及本地或云模型。 |
| **5。执行** | 自动内存等待活动工作，释放不需要的模型并重新加载所需的资源。 1–10 作业系列按顺序运行，并在下一个作业之前释放资源。云提供商使用选定的帐户和配置。 |
| **6。检索和重用** | 将媒体保存在 Novera 系统文件夹中，显示结果和可用计时，然后提供变体、库、复制、导出或系统共享。发送到另一个应用程序仍然是您的操作。 |

自动化涵盖集成引擎和工作流程；它并不使每个 Hub 模型都可执行。硬件、安装的组件和提供商访问权限决定了哪些内容可以运行。文件夹、文件更改和 shell 命令遵循对话的访问授权。

[用户指南](docs/USER_GUIDE.md) · [引擎和验证](docs/SUIVI_MOTEURS.md) · [发展](docs/DEVELOPMENT.md)

对于 1.0.1，LFM3-Omni-2B Q4_K_M 及其必需的 `mmproj-LFM3-Omni-2B-Q4_K_M.gguf` 是桌面和移动设备上的默认建议； NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M 仍然是纯文本替代方案。桌面上的初始上下文是 32,768 令牌，移动设备上的初始上下文是 2,048。较长的上下文使用更多的内存。现有的模型选择和设置将被保留，直到明确更改为止。

## 集线器及兼容型号

**GGUF、标准和量化 Safetensors、ONNX 和 MLX**：按任务探索模型并选择与引擎和硬件兼容的变体。

| 家庭 | 源码支持 | 要求 |
| --- | --- | --- |
| **GGUF** | 通过 llama.cpp 生成文本；支持相应配置的图像和视频组件。 | 捆绑引擎识别的架构。 |
| **分体式 GGUF** | 每个完整系列一个变体、总大小、全分片下载和大小/SHA-256/标头检查。 | 标准编号文件名；下载 500 GB 并不意味着该型号适合此 PC. |
| **标准Safetensors** | 通过 Transformers 加载完整模型文件夹，在 CPU 或 NVIDIA CUDA 上进行自回归文本生成。 | 配置、标记器和每个所需的分片。 |
| **ONNX Runtime** | 本地导入数字/布尔图并准备 GenAI 文本导出。 | 已验证的完整文件夹；需要特定于任务的预处理/后处理； [设置和限制](onnx-server/README.md). |
| **LoRA / PEFT 适配器** | 在 Safetensors 提供程序中导入完整的基础及其单独的本地适配器。 | 未量化因果 Transformers 基数、匹配身份、张量检查和累积内存估计； [设置和限制](transformers-server/README.md#local-lora--peft-adapters). |
| **FP8 LLM / ModelOpt** | 原生 CUDA 执行，用于兼容密集 Llama/Qwen2/Qwen3 每个张量 FP8 导出。 | 架构/张量检查和真实内核探测； [设置和限制](transformers-server/README.md#modelopt-fp8-and-nvfp4-llms). |
| **NVFP4 LLM / ModelOpt** | 通过原生 CUDA GEMM 进行打包块 16 FP4 投影；与图像 NVFP4 分开。 | 兼容Blackwell GPU，支持尺寸/导出和实际内核探针；已在 RTX 5070 上使用未训练的测试模型验证。 |
| **AWQ** | 未融合算子的 4 位 GEMM 检查点。 | NVIDIA CUDA 和可选的 GPTQModel/Transformers 装载机。 |
| **GPTQ** | 2/3/4/8 位配置，gptq/gptq_v2 格式。 | NVIDIA CUDA、GPTQModel 和 Optimum；实际执行在 4 位进行测试。 |
| **bitsandbytes** | 4 位 NF4/FP4 或 8 位 INT8. | NVIDIA CUDA 和可选依赖项；真实的NF4和INT8测试。 |
| **EXL3** | 通过 ExLlamaV3 加载完整的量化 Safetensors 文件夹；已测试实际 CUDA 生成。 | NVIDIA GPU，独立的Python 3.12环境和兼容架构； no CPU fallback. |
| **EXL2** | 专用 ExLlamaV2 加载器；已在 GPU 上测试流式输出、取消和模型卸载。 | 在受测软件环境中明确选择 CUDA Attention 后端；需要完整的模型检查点和足够可用的 VRAM。 |
| **MLX** | Apple Silicon 上的兼容型号。 | MLX 引擎及支持平台。 |

集线器现已固定 **LFM3-1.7B** 作为其兼容配置的 LiquidAI 推荐，具有 Q4_K_M、Q6_K 和 Q8_0 变体。首次运行的模型仍然是上面指导配置中列出的模型。

过滤下载权重 **1 GB 至 500 GB 及以上**，然后按硬件适合度、大小、新近度或下载次数排序。结果逐渐加载；过滤器适用于获取的模型及其默认变体。内存建议使用可用的 RAM/VRAM、上下文和配套组件，而不重复计算共享 GPU 内存。

AWQ 4 位、GPTQ 4 位、NF4 和 INT8 均使用离线创建的未经训练的微型模型在 RTX 5070 Laptop 上生成文本。这验证了加载和执行，而不是每个模型的质量或性能。 **这些添加在源码中：需要重建和兼容依赖；此 README 更新不会升级已安装的二进制文件。**

**在 RTX 5070 Laptop 上测量：** Qwen2.5-0.5B-Instruct，上下文 2,048，提示 272 令牌，128 生成的令牌，五次预热运行：中值解码 **GGUF Q4_K_M 402.7 tokens/s · EXL3 4 bpw 312.5 · EXL2 4 bpw 146.9**. 本次未证明相对 GGUF 有速度优势。量化与校准方式不同，且 EXL3 未通过一道基础算术测试；这些结果不构成通用的速度或质量排名。 [完整测量和限制](deliverables/exllama-2026-10-30/validation.md).

**TabbyAPI** 是可选的、单独管理的 OpenAI 兼容服务器连接，默认情况下禁用。测试了经过身份验证的 EXL3 模型发现和流式传输。受管理的本地 ExLlama 路由仍然不同。 [ExLlama 设置和 TabbyAPI 连接](transformers-server/README.md#exl3-first-exl2-second--nvidia-execution).

默认的硬件适应排序有利于相同兼容性和可用内存层中的较新版本。已安装的模型不会自动替换。

[量化 Safetensors 设置](transformers-server/README.md#quantized-safetensors--source-integration-29-october-2026) · [格式、优先级和验证](docs/SUIVI_MOTEURS.md)

更新的来源添加 **Windows x64 配置中的可选托管组件**：私有Python环境，固定CPU/CUDA配置文件，下载、验证、修复和删除之前的估计和确认。自定义解释器路径保留在高级选项下。原生 GGUF 引擎保留其现有组件；移动和云不下载桌面Python/PyTorch。已使用合成测试数据验证三个专用 CPU/导出配置；维护者报告 2026年11月1日 成功桌面使用； GPU 配置文件和干净的 PC 安装仍然需要单独、详细的验证。 [配置文件和测试限制](docs/REPRISE_COMPOSANTS_GERES_80_LANGUES.md)。将堆栈嵌入 EXE 被推迟。

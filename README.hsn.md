## Novera 1.0.1

Novera 1.0.1 适用于下列平台。下载适合您的系统的软件包或使用其签名的更新通道。当您安装新软件包或接受更新时，现有安装会更新。

- 安全性：对远程页面更严格的本机权限、网络 API 和服务器工具的身份验证、受保护的秘密存储和迁移、更安全的文件/媒体访问、电子表格解析和构建脚本。公开的依赖项已更新；其余的建议将被公开追踪。
- 隐私：统计信息和错误报告需要单独同意，默认情况下保持关闭状态。构建包括记录的目标配置。技术诊断被过滤；用户可以控制激活。
- 本地引擎：`llama.cpp v0.9.0` (`b12110`, `cd959bae99ff4bed22bef2604f45241c09bbb8c8`)。引擎版本和应用程序版本是分开的。初始模型设置和模型/投影仪注册已得到纠正，包括涉及 `kv_unified` 的启动失败。现有的个人设置将被保留。
- 语言：24 其他语言和变体将界面和翻译后的 README 集合带到 104，每个目录有 2,435 个界面密钥。此报道并不能证明每种语言的本地编辑质量或语音支持。
- **LFM3-Omni-2B Q4_K_M** — 电脑跟手机上默认用个模型。适合文字、图像搭音频个小模型，要有配套个 `mmproj` 文件。两个文件下载大约 1.39 GB。要轻便个多模态配置好选伊。语音功能看平台搭引擎，长上下文要用更多内存。
- **NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M** — 只做文字个备选模型，支持对话、写作、工具搭结构化回答。下载大约 6.18 GB。比 LFM3-Omni 要更多内存，本身勿处理图像搭音频。朗读回答用系统语音。内存足个辰光好选来做文字工作，事实要拿来源核对。

- 麦克风状态：绿色表示可用，红色表示忙碌，灰色表示不可用。识别、听力重新启动、焦点处理和可见听写均已得到纠正。原生音频模型语音目前在 Windows 上实现；其他平台仍然需要本机验证和合适的语音支持。
- 网络：更可靠的天气请求检测、当前日期指南、最新结果和引用，以及工具使用后以当前请求为中心的答案。语音省略了装饰性来源标签和链接，同时保留可见的引用。只要所选模型支持，响应和语音语言就会遵循用户的语言。

- 舒适：下部控件折叠，同时输入保持可见。紧凑的麦克风和披露控件、麦克风下方的声音按钮、响应式音乐设置和翻译的组件标签改善了小屏幕上的使用。

## 从首次启动到结果

**我们的自动化将准备工作与完整的执行工作流程连接起来。** Novera 处理所选配置可用的技术步骤，同时保持高级控件的可访问性。

| 步骤 | Novera 处理的内容 |
| --- | --- |
| **1. 开始** | 在首次启动时选择受支持的系统语言并保存您的偏好。展示起始模型和有用的硬件信息。 |
| **2. 准备** | 引导安装提供文本、嵌入、图像、音乐、视频和升频。在您批准前预览组件、大小和可用空间，然后使用进度、暂停/恢复和 SHA-256 验证跟踪下载。 |
| **3. 配置** | 注册模型及其组件，准备相关配置文件并报告所需依赖项。检索嵌入在 CPU 上以保存的 CPU/GPU 选择开始。新的音乐配置文件默认为器乐模式。 |
| **4. 理解请求** | 自动将识别的创建请求路由到文本、图像、音乐或视频。您也可以明确选择输出模式和本地或云模型。 |
| **5. 执行** | 自动内存等待活动工作，释放不需要的模型并重新加载所需资源。1–10 作业系列按顺序运行，并在下一个作业前释放资源。云提供商使用所选账户和配置。 |
| **6. 检索和重用** | 将媒体保存到 Novera 系统文件夹中，显示结果和可用时间，然后提供变体、库、复制、导出或系统共享。发送到另一个应用程序仍是您的操作。 |

自动化涵盖集成引擎和工作流程；它不会使每个 Hub 模型可执行。硬件、已安装的组件和提供商访问权限决定了什么可以运行。文件夹、文件更改和 shell 命令遵循对话的访问授权。

## 源中的能力

| 区域 | 功能 |
| --- | --- |
| **文字與圖像理解** | 对话、文档附件、流式回复以及本地或云模型。视觉依赖于模型；理解和生成图像是独立的能力。 |

| **搜索和工具** | 根据模型支持和授予的访问权限，提供网络搜索、基于嵌入的文档检索、MCP、工作区和本地工具。 |

| **资源管理** | 默认启用自动内存，支持组件的 CPU/GPU 设置以及资源允许时的手动配置。 |

## 中心和兼容模型

**GGUF, 标准和量化后的 Safetensors, ONNX 和 MLX**: 按任务探索模型并选择与引擎和您的硬件兼容的变体。

| 家族 | 源代码中的支持 | 要求 |
| --- | --- | --- |
| **GGUF** | 通過 llama.cpp 進行文本生成；支持的配置文件的圖像和視頻組件。 | 由捆绑引擎识别的架构。 |
| **拆分 GGUF** | 每个完整系列一个变体，总大小，所有分片下载和大小/SHA-256/头检查。 | 标准编号文件名；下载 500 GB 不意味着该模型适用于此 PC. |
| **标准 Safetensors** | 通过 Transformers 的完整文件夹，CPU 或 NVIDIA CUDA 上的因果文本。 | 配置、分词器和所有必需的分片。 |
| **ONNX Runtime** | 本地导入数值/布尔图和准备好的 GenAI 文本导出。 | 已验证的完整文件夹；需要特定于任务的预处理/后处理； [设置和限制](onnx-server/README.md). |
| **LoRA / PEFT 适配器** | 在 Safetensors 提供者中导入包含其独立本地适配器的完整基础模型。 | 未量化因果Transformers基，匹配身份、张量检查和累积内存估计; [设置和限制](transformers-server/README.md#local-lora--peft-adapters). |
| **FP8 LLM / ModelOpt** | 原生CUDA执行，适用于兼容的密集Llama/Qwen2/Qwen3每张量FP8导出。 | 架构/张量检查和真实内核探测; [设置和限制](transformers-server/README.md#modelopt-fp8-and-nvfp4-llms). |
| **NVFP4 LLM / ModelOpt** | 通过原生CUDA GEMM的打包块-16 FP4投影；独立于图像NVFP4。 | 兼容的Blackwell GPU，支持的维度/导出和实际内核探测；在RTX 5070上测试未训练的测试模型。 |
| **AWQ** | 不含操作融合的 4-bit GEMM 模型檢查點。 | NVIDIA CUDA和可选的GPTQModel/Transformers加载器。 |
| **GPTQ** | 2/3/4/8-bit配置，gptq/gptq_v2格式。 | NVIDIA CUDA、GPTQModel和Optimum；在4位上测试真实执行。 |
| **bitsandbytes** | 4-bit NF4/FP4 或 8-bit INT8. | NVIDIA CUDA和可选依赖项；真实的NF4和INT8测试。 |
| **EXL3** | 透過 ExLlamaV3 載入完整的量化 Safetensors 模型資料夾；已使用 CUDA 進行實際生成測試。 | NVIDIA GPU，独立的Python 3.12环境和兼容的架构；无CPU回退。 |
| **EXL2** | 专用ExLlamaV2加载器；在GPU.上测试流式传输、取消和卸载 | 受测软件环境须明确选择 CUDA Attention backend；需要完整模型 checkpoint 和足够可用 VRAM。 |
| **MLX** | Apple Silicon上的兼容模型。 | MLX引擎和支持的平台。 |

The Hub 现在固定 **LFM3-1.7B** 作为其 LiquidAI 兼容配置的推荐，包含 Q4_K_M、Q6_K 和 Q8_0 变体。首次运行的模型仍为上述引导配置中列出的模型。

从下载权重过滤 **在 1 GB 到 500 GB 及以上范围内**然后按硬件匹配度、大小、新近度或下载量排序。结果逐步加载；过滤器应用于已获取的模型及其默认变体。内存建议使用可用 RAM/VRAM、上下文和配套组件，不重复计算共享的 GPU 内存。

AWQ 4-bit、GPTQ 4-bit、NF4 和 INT8 各自使用离线创建的微小未训练模型在 RTX 5070 Laptop 上生成文本。这验证了加载和执行，而非每个模型的质量或性能。 **这些添加项在源文件中：需要重建和兼容的依赖项；此 README 更新不升级已安装的二进制文件。**

**在 RTX 5070 Laptop 上测量：** Qwen2.5-0.5B-Instruct、上下文 2,048、提示 272 令牌、128 生成的令牌，五次预热运行：中位数解码 **GGUF Q4_K_M 402.7 tokens/s · EXL3 4 bpw 312.5 · EXL2 4 bpw 146.9**在此未证明相对于 GGUF 有速度优势。量化/校准不同，且 EXL3 在一个简单算术测试中失败；这些结果不是一般的速度或质量排名。 [完整的测量和限制](deliverables/exllama-2026-10-30/validation.md).

**TabbyAPI** 是一个可选的、单独管理的 OpenAI 兼容服务器连接，默认禁用。已测试了经过身份验证的 EXL3 模型发现和流式传输。受管的本地 ExLlama 路由保持独立。 [ExLlama 设置和 TabbyAPI 连接](transformers-server/README.md#exl3-first-exl2-second--nvidia-execution).

默认的硬件适配排序倾向于同一兼容性和可用内存层级内的较新版本。已安装的模型不会自动替换。

[量化 Safetensors 设置](transformers-server/README.md#quantized-safetensors--source-integration-29-october-2026) · [格式、优先级和验证](docs/SUIVI_MOTEURS.md)

更新的源添加了 **Windows x64 配置中的可选管理组件**: 私有 Python 环境，固定的 CPU/CUDA 配置，下载前的估算和确认，验证、修复和移除。自定义解释器路径保留在高级选项下。原生 GGUF 引擎保留现有组件；移动和云端不下载桌面 Python/PyTorch。三个私有 CPU/导出配置已使用真实合成测试数据进行测试；维护者报告在 2026年11月1日成功在桌面使用；GPU 配置和干净的 PC 安装仍需要单独、详细的验证。 [配置和测试限制](docs/REPRISE_COMPOSANTS_GERES_80_LANGUES.md). 将堆栈嵌入 EXE 已推迟。

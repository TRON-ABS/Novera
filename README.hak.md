## Novera 1.0.1

Novera 1.0.1 適用於下列平台。下載適合您的系統的軟體包或使用其簽署的更新通道。當您安裝新軟體包或接受更新時，現有安裝會更新。

- 安全性：對遠端頁面更嚴格的本機權限、網路 API 和伺服器工具的身份驗證、受保護的秘密儲存和遷移、更安全的檔案/媒體存取、電子表格解析和建置腳本。公開的依賴項已更新；其餘的建議將被公開追蹤。
- 隱私權：統計資訊和錯誤報告需要單獨同意，預設保持關閉狀態。建置包括記錄的目標配置。技術診斷被過濾；使用者可以控制啟動。
- 本機引擎：`llama.cpp v0.9.0` (`b12110`, `cd959bae99ff4bed22bef2604f45241c09bbb8c8`)。引擎版本和應用程式版本是分開的。初始模型設定和模型/投影機註冊已修正，包括涉及 `kv_unified` 的啟動失敗。現有的個人設定將被保留。
- 語言：24 其他語言和變體將介面和翻譯後的 README 集合帶到 104，每個目錄有 2,435 個介面金鑰。此報導並不能證明每種語言的本地編輯品質或語音支援。
- **LFM3-Omni-2B Q4_K_M** — 桌面摎手機个預設模型。輕量模型做得處理文字、圖像摎音訊，需要配套个 `mmproj` 檔案。兩隻檔案下載約 1.39 GB。想要較輕个多模態設定做得揀佢。語音功能愛看平台摎引擎，較長个上下文會用較多記憶體。
- **NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M** — 純文字个替代模型，支援對話、寫作、工具摎結構化回答。下載約 6.18 GB。比 LFM3-Omni 愛較多記憶體，本身毋處理圖像抑係音訊。朗讀回答用系統語音。記憶體罅額時做得揀來做文字工作，事實愛用來源核對。
- 對於 1.0.1，LFM3-Omni-2B Q4_K_M 及其所需的 `mmproj-LFM3-Omni-2B-Q4_K_M.gguf` 是桌面和行動裝置上的預設建議； NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M 仍然是純文字替代方案。桌面上的初始上下文是 32,768 令牌，行動裝置上的初始上下文是 2,048。較長的上下文使用更多的記憶體。現有的模型選擇和設定將被保留，直到明確更改為止。
- 語音：LFM3-Omni直接本地麥克風輸入，連續對話和自動發送，音頻模型有男/女回复聲音，經典模型有系統語音。回覆閱讀也適用於鍵入的訊息和重新生成，與麥克風捕獲無關。一個小聲音按鈕可以啟用或靜音閱讀。
- 麥克風狀態：綠色表示可用，紅色表示忙碌，灰色表示不可用。辨識、聽力重新啟動、焦點處理和可見聽寫均已修正。原生音訊模型語音目前在 Windows 上實現；其他平台仍需要本機驗證和適當的語音支援。
- 網路：更可靠的天氣請求檢測、當前日期指南、最新結果和引用，以及工具使用後以當前請求為中心的答案。語音省略了裝飾性來源標籤和鏈接，同時保留可見的引用。只要所選模型支持，回應和語音語言就會遵循使用者的語言。

| **1。開始** | 第一次啟動時選定支援系統語言並儲存你偏好。呈現起始模型同有用硬體資訊。 |
| **2. 準備** | 引導安裝提供文字、嵌入、圖像、音樂、影片及升級。喺你批准前，佢會預覽組件、尺寸同空閒空間，之後會用進度、暫停/恢復同SHA-256驗證追蹤下載。 |
| **3. 設定** | 登記模型同佢嘅組件，準備相關設定檔同報告所需依賴。檢索嵌入喺CPU開始，用咗儲存嘅CPU/GPU選擇。新音樂設定預設為樂器模式。 |
| **4. 理解請求** | 自動路由識別嘅創建請求至文字、圖像、音樂或影片。你亦可以明確選擇輸出模式同本地或雲端模型。 |
| **5. 執行** | 自動記憶體等候活躍工作，釋放唔需要嘅模型同重新載入所需資源。一個1–10工作系列按順序運行，喺下一個工作前釋放資源。雲端提供者使用所選帳戶同設定。 |
| **6. 檢索並重用** | 喺Novera系統文件夾儲存媒體，顯示結果同可用時間，之後提供變體、圖庫、複製、匯出或系統分享。傳送至其他應用程式仍係你嘅操作。 |

自動化涵蓋整合引擎同工作流程；佢唔會令每個Hub模型都可執行。硬體、已安裝組件同提供者存取決定咗乜嘢可以運行。文件夾、檔案變更同Shell指令跟隨對話嘅存取權限。

## 樞紐同相容模型

**GGUF, 標準同量化 Safetensors, ONNX, 同 MLX**: 依任務探索模型並揀相容於引擎同你硬體嘅變體。

| 系列 | 源碼支援 | 要求 |
| --- | --- | --- |
| **GGUF** | 透過 llama.cpp 文本生成；支援檔案嘅圖像同影片組件。 | 由捆綁引擎認可嘅架構。 |
| **拆分 GGUF** | 每完整系列一變體，總大小，全分片下載同大小/SHA-256/標頭檢查。 | 標準編號檔名；下載 500 GB 唔代表模型適合呢個 PC. |
| **標準 Safetensors** | 透過 Transformers 嘅完整資料夾，因果文本喺 CPU 或 NVIDIA CUDA 上。 | 配置、分詞器同所有所需分片。 |
| **ONNX Runtime** | 本地匯入數值/布林圖表同準備好嘅 GenAI 文本輸出。 | 已驗證完整資料夾；需要任務特定預處理/後處理； [設置同限制](onnx-server/README.md). |
| **LoRA / PEFT 轉接器** | 喺 Safetensors 供應者中匯入完整基礎同佢獨立嘅本地轉接器。 | 未量化因果 Transformers 基礎，符合恆等、張量檢查及累積記憶估計； [設置同限制](transformers-server/README.md#local-lora--peft-adapters). |
| **FP8 LLM / ModelOpt** | 相容稠密 Llama/Qwen2/Qwen3 逐張量 FP8 匯出之原生 CUDA 執行。 | 架構/張量檢查及真實核心探測； [設置同限制](transformers-server/README.md#modelopt-fp8-and-nvfp4-llms). |
| **NVFP4 LLM / ModelOpt** | 封裝區塊-16 FP4 投影經原生 CUDA GEMMs；獨立於圖像 NVFP4。 | 相容 Blackwell GPU，支援維度/匯出及真實核心探測；未訓練測試模型在 RTX 5070 上測試。 |
| **AWQ** | 無運算融合嘅 4-bit GEMM 模型檢查點。 | NVIDIA CUDA 及可選 GPTQModel/Transformers 載入器。 |
| **GPTQ** | 2/3/4/8-位元配置，gptq/gptq_v2 格式。 | NVIDIA CUDA, GPTQModel 及 Optimum；在 4 位元上進行真實執行測試。 |
| **bitsandbytes** | 4-位元 NF4/FP4 或 8-位元 INT8. | NVIDIA CUDA 及可選依賴；原生 NF4 及 INT8 測試。 |
| **EXL3** | 完整量化 Safetensors 模型資料夾經由 ExLlamaV3 載入；已用 CUDA 測試實際生成。 | NVIDIA GPU，獨立 Python 3.12 環境及相容架構；無 CPU 備援。 |
| **EXL2** | 專用 ExLlamaV2 載入器；GPU. 上串流、取消及卸載測試。 | 受測軟體環境須明確選用 CUDA Attention backend；需要完整模型 checkpoint 同足夠可用 VRAM。 |
| **MLX** | Apple Silicon 上相容模型。 | MLX 引擎及相容平台。 |

樞紐現已鎖定 **LFM3-1.7B** 按其 LiquidAI 建議相容配置，包含 Q4_K_M、Q6_K 佮 Q8_0 變體。初次運行模型仍係上文引導配置所列者。

由...過濾下載權重 **由 1 GB 至 500 GB 佮以上**，隨後按硬體適配、大小、新舊或下載量排序。結果漸進載入；過濾適用於獲取模型佮其預設變體。記憶體建議使用可用 RAM/VRAM、上下文佮伴隨組件，毋會重複計算共享 GPU 記憶體。

AWQ 4-bit、GPTQ 4-bit、NF4 佮 INT8 各生成文字於 RTX 5070 Laptop，使用離線創建的微小未訓練模型。此驗證載入佮執行，毋係每個模型的品質或性能。 **此新增係於源碼中：需要重建佮相容依賴；此 README 更新毋會升級已安裝的二進制文件。**

**於 RTX 5070 Laptop 上測量：** Qwen2.5-0.5B-Instruct、上下文 2,048、提示 272 令牌、128 生成令牌，五次預熱運行：中位數解碼 **GGUF Q4_K_M 402.7 tokens/s · EXL3 4 bpw 312.5 · EXL2 4 bpw 146.9**。毋有比 GGUF 嘅速度優勢。量化/校準不同，佮 EXL3 失敗一次簡單算術測試；此結果毋係一般速度或品質排名。 [完整測量佮限制](deliverables/exllama-2026-10-30/validation.md).

**TabbyAPI** 係一個可選、獨立管理的 OpenAI 相容伺服器連接，預設關閉。已認證 EXL3 模型發現佮串流已測試。經管的本地 ExLlama 路徑仍獨立。 [ExLlama 設定佮 TabbyAPI 連接](transformers-server/README.md#exl3-first-exl2-second--nvidia-execution).

預設硬體適應排序偏好同相容佮可用記憶體層級內較新版本。已安裝模型毋會自動替換。

[量化 Safetensors 設定](transformers-server/README.md#quantized-safetensors--source-integration-29-october-2026) · [格式、優先級佮驗證](docs/SUIVI_MOTEURS.md)

更新的源碼增加 **Windows x64 系統中配置裡可選管理組件**: 私人 Python 環境、固定 CPU/CUDA 設定檔、下載前估算同確認、驗證、修復同移除。自訂解譯器路徑留喺進階選項之下。原生 GGUF 引擎保留現有組件；行動同雲端唔會下載桌面 Python/PyTorch。三個私人 CPU/匯出設定檔用真合成測試資料測試；維護者報告 2026年11月1日桌面使用成功；GPU 設定檔同乾淨-PC 安裝仍需分開詳細驗證。 [設定檔及測試限制](docs/REPRISE_COMPOSANTS_GERES_80_LANGUES.md). 將堆疊嵌入 EXE 延後處理。

## バージョン 1.0.1 を準備中です

公開ダウンロードは 1.0.0 のままです。 1.0.1 のソースには次の改善が用意されています。パッケージの再構築、リリースのチェック、公開が必要です。このドキュメントを更新しても、インストールされているアプリケーションは更新されません。

- セキュリティ: リモート ページのネイティブ アクセス許可の厳格化、ネットワーク API とサーバー ツールの認証、保護された秘密のストレージと移行、より安全なファイル/メディア アクセス、スプレッドシートの解析とスクリプトの構築。公開された依存関係が更新されました。残りの勧告はオープンに追跡されます。
- プライバシー: 統計とエラーレポートには個別の同意が必要であり、デフォルトではオフのままです。ビルドには、文書化された宛先構成が含まれます。技術的な診断はフィルタリングされます。ユーザーはアクティベーションを制御できます。
- ローカル エンジン: `llama.cpp v0.9.0` (`b12110`, `cd959bae99ff4bed22bef2604f45241c09bbb8c8`)。エンジンのバージョンとアプリケーションのバージョンは別です。 `kv_unified` に関連する起動の失敗を含む、モデルの初期設定とモデル/プロジェクターの登録が修正されました。既存の個人設定は保持されます。
- 言語: 24 個の追加言語とバリアントにより、インターフェースと翻訳された README コレクションが 104 に提供され、カタログごとに 2,435 個のインターフェース キーが提供されます。この報道は、すべての言語でのネイティブの編集品質やスピーチのサポートを保証するものではありません。
- **LFM3-Omni-2B Q4_K_M** — デスクトップとモバイルのデフォルト。必要な `mmproj` ファイルを使用した、テキスト、画像、オーディオのコンパクトなモデル。ダウンロード: どちらのファイルも約 1.39 GB です。軽量のマルチモーダルセットアップにはこれを選択してください。音声機能はプラットフォームとエンジンによって異なります。コンテキストが長くなると、より多くのメモリが使用されます。
- **NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M** — 会話、執筆、ツール、構造化された回答のためのテキストのみの代替手段。ダウンロード: 約 6.18 GB。 LFM3-Omni よりも多くのメモリを必要とし、画像や音声自体は処理しません。音声応答ではシステム音声が使用されます。十分なメモリがある場合は、テキスト タスクにこれを選択してください。情報源を使って事実に基づいた答えを確認してください。
- 1.0.1 の場合、LFM3-Omni-2B Q4_K_M とその必須の `mmproj-LFM3-Omni-2B-Q4_K_M.gguf` がデスクトップとモバイルでのデフォルトの推奨事項です。 NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M は引き続きテキストのみの代替手段です。初期コンテキストはデスクトップでは 32,768 トークン、モバイルでは 2,048 です。コンテキストが長いほど、より多くのメモリが使用されます。既存のモデルの選択と設定は、明示的に変更されるまで保持されます。
- 音声: LFM3-Omni の直接ローカル マイク入力、連続会話と自動送信、オーディオ モデルの男性/女性応答音声、クラシック モデルのシステム音声。返信の読み取りは、マイクのキャプチャとは関係なく、入力されたメッセージと再生成にも機能します。小さなサウンド ボタンを押すと、読み上げが有効になったり、ミュートになったりします。
- マイクのステータス: 使用可能な場合は緑色、通話中は赤色、使用できない場合は灰色。認識、リスニングの再開、フォーカス処理、および表示されるディクテーションが修正されました。ネイティブ オーディオ モデルの音声は現在、Windows に実装されています。他のプラットフォームでは依然としてネイティブ検証と適切な音声サポートが必要です。
- Web: より信頼性の高い気象リクエストの検出、最新の日付のガイダンス、最新の結果と引用、ツール使用後の現在のリクエストを中心とした回答。スピーチでは、目に見える引用を維持しながら、装飾的なソースラベルとリンクを省略します。選択したモデルがサポートしている限り、応答と音声言語はユーザーの言語に従います。
- 最適化: インターネットが有効なときにバックグラウンドで Web 検索を準備し、サービスの起動を共有し、再生に先立って次の音声セグメントを準備し、文の連続性を向上させます。フランスの年、10 進数、単位がより自然に読み取れるようになりました。ネットワークの遅延とモデルの速度は依然としてセットアップに依存します。
- 快適さ: 入力は表示されたままですが、下部のコントロールは折りたたまれます。コンパクトなマイクと開示コントロール、マイクの下のサウンド ボタン、応答性の高い音楽設定、および翻訳されたコンポーネント ラベルにより、小さな画面での使用が向上します。
- API カタログ: ローカルの TabbyAPI を含む 43 プロバイダー プロファイル。更新されたチャットとメディアの選択が含まれます。新しいエントリには、サポートされている場合、GPT-6.1 Terra, Kimi K3.1 Pro, MiniMax M3.1 Flash, GLM 5.3 Flash, Hy4 と GPT Image 2.6, Gemini Omni 1.2, FLUX 3 が含まれます。更新しても 10 モデルを超える結果は非表示になりません。正確な識別子、地域エンドポイント、プライベート展開、インポートされたモデルが尊重されます。
- 検証: 対象のアプリケーション、ネイティブ ライブラリ、パブリック カタログ、および言語のチェックが詳細なメモに記録されます。インターフェースは Windows / macOS / Linux / Android / iOS 用にビルドされます。これらのフロントエンド ビルドは、すべてのデバイス上のネイティブ パッケージまたは推論を認証するものではありません。

## すべての作品に 1 つのダッシュボード

Novera はあなたとともに成長します。あなたの例と設定は、他のユーザーが適切な設定を見つけるのに役立ちます。質問、問題、アイデアを共有してください [Facebook page](https://www.facebook.com/profile.php?id=61596114515071) または [メール](mailto:contact.novera.tronabs@gmail.com)。可能であれば、Novera バージョン、デバイス、ローカル/API モデルを含めてください。個人情報を削除し、API キーやパスワードを決して共有しないでください。

![Novera で生成されたイメージと、数量、シード、アップスケーリング、自動メモリを備えた統合ダッシュボード](.github/assets/novera-dashboard-2026-11-01.png)

*2026年11月1日 のメンテナによって提供された実際の Windows アプリケーションのスクリーンショット。アプリケーションが正常に動作すると報告しています。生成されたランドスケープ、その保存されたファイル コントロール、および統合された作成ダッシュボードが表示されます。これはモックアップではありません。*

1 つのパネル、5 つのモード: **オート / テキスト / 画像 / 音楽 / ビデオ**。コントロールは、選択したモード (比率、解像度、デュレーション、リズム、品質、インストゥルメンタル、歌詞、シード、量) に従います。パネルの幅とボタンは、ウィンドウと翻訳されたラベルに適応します。

- **1–10 連続生成**、デフォルトは 1 で、画像、音楽、ビデオに独立した量が含まれます。 「停止」は、アクティブなタスクと残りのキューをキャンセルします。
- **ランダム、固定、+1 および −1 シード**、プリセットまたはカスタム比率およびオプション **Real-ESRGAN ×2/×4** 最終寸法が表示された状態でアップスケーリングします。
- 選択したモデル、自動メモリ、添付ファイル、説明書、Web 検索、ツールは同じバーに表示されます。ツールはモデルの機能と許可されたアクセスに依存します。

## 最初の立ち上げから結果まで

**当社の自動化により、準備から完全な実行ワークフローが接続されます。** Novera は、高度なコントロールへのアクセスを維持しながら、選択した構成で利用可能な技術的な手順を処理します。

| ステップ | Noveraが扱うもの |
| --- | --- |
| **1。スタート** | 初回起動時にサポートされているシステム言語を選択し、設定を保存します。スターティングモデルや役立つハードウェア情報を紹介します。 |
| **2。準備する** | ガイド付きインストールでは、テキスト、埋め込み、画像、音楽、ビデオ、アップスケーリングが提供されます。承認前にコンポーネント、サイズ、空き容量をプレビューし、ダウンロードの進行状況、一時停止/再開、SHA-256 検証を追跡します。 |
| **3。設定する** | モデルとそのコンポーネントを登録し、関連するプロファイルを準備し、必要な依存関係をレポートします。検索埋め込みは、保存された CPU/GPU の選択を使用して CPU から始まります。新しい音楽プロファイルはデフォルトでインストゥルメンタル モードになります。 |
| **4。リクエストを理解する** | 認識された作成リクエストをテキスト、画像、音楽、またはビデオに自動ルーティングします。出力モードとローカルまたはクラウド モデルを明示的に選択することもできます。 |
| **5。実行する** | 自動メモリはアクティブな作業を待機し、不要なモデルを解放し、必要なリソースをリロードします。 1 ～ 10 ジョブ シリーズは順番に実行され、次のジョブの前にリソースを解放します。クラウド プロバイダーは、選択されたアカウントと構成を使用します。 |
| **6。取得して再利用する** | メディアを Novera システム フォルダーに保存し、結果と利用可能なタイミングを表示し、バリアント、ライブラリ、コピー、エクスポート、またはシステム共有を提供します。別のアプリケーションへの送信は、ユーザーのアクションのままです。 |

## ハブと対応機種

**GGUF、標準および量子化された Safetensors、ONNX、および MLX**: タスクごとにモデルを探索し、エンジンとハードウェアと互換性のあるバリアントを選択します。

| 家族 | ソースでのサポート | 要件 |
| --- | --- | --- |
| **GGUF** | llama.cpp によるテキスト生成。対応プロファイルでは画像・動画コンポーネントも利用可能。 | バンドルされたエンジンによって認識されるアーキテクチャ。 |
| **分割 GGUF** | 完全なシリーズごとに 1 つのバリアント、合計サイズ、全シャードのダウンロード、およびサイズ/SHA-256/ヘッダーのチェック。 | 標準の番号付きファイル名。 500 GB をダウンロードしても、モデルがこの PC. に適合するわけではありません |
| **標準 Safetensors** | Transformers で完全なモデルフォルダーを読み込み、CPU または NVIDIA CUDA で自己回帰型のテキスト生成を実行。 | 構成、トークナイザー、および必要なすべてのシャード。 |
| **ONNX Runtime** | 数値/ブールグラフのローカルインポートと準備された GenAI テキストエクスポート。 | 完全なフォルダーが検証されました。タスク固有の前処理/後処理が必要。 [設定と制限](onnx-server/README.md). |
| **LoRA / PEFT アダプター** | Safetensors プロバイダーの個別のローカル アダプターを含む完全なベースをインポートします。 | 量子化されていない因果関係 Transformers ベース、一致する同一性、テンソル チェック、および累積メモリ推定。 [設定と制限](transformers-server/README.md#local-lora--peft-adapters). |
| **FP8 LLM / ModelOpt** | 互換性のある高密度 Llama/Qwen2/Qwen3 テンソルごとの FP8 エクスポートのためのネイティブ CUDA 実行。 | アーキテクチャ/テンソル チェックと実際のカーネル プローブ。 [設定と制限](transformers-server/README.md#modelopt-fp8-and-nvfp4-llms). |
| **NVFP4 LLM / ModelOpt** | ネイティブ CUDA GEMM を介したパックされたブロック 16 FP4 プロジェクション。画像NVFP4とは別のものです。 | 互換性のある Blackwell GPU、サポートされるディメンション/エクスポートおよび実際のカーネル プローブ。RTX 5070 で未学習のテストモデルを使用して検証しました。 |
| **AWQ** | 演算を融合していない 4 ビット GEMM チェックポイント。 | NVIDIA CUDA およびオプションの GPTQModel/Transformers ローダー。 |
| **GPTQ** | 2/3/4/8 ビット構成、gptq/gptq_v2 フォーマット。 | NVIDIA CUDA、GPTQModel、Optimum;実際の実行は 4 ビットでテストされます。 |
| **bitsandbytes** | 4 ビット NF4/FP4 または 8 ビット INT8. | NVIDIA CUDA およびオプションの依存関係。実際の NF4 および INT8 テスト。 |
| **EXL3** | ExLlamaV3 で完全な量子化 Safetensors フォルダーを読み込み。CUDA での実際の生成をテスト済み。 | NVIDIA GPU、別の Python 3.12 環境と互換性のあるアーキテクチャ。 CPU フォールバックはありません。 |
| **EXL2** | 専用の ExLlamaV2 ローダー。ストリーミング、キャンセル、モデルのメモリ解放を GPU でテスト済み。 | テストしたソフトウェア構成では CUDA Attention バックエンドを明示的に選択。完全なモデルチェックポイントと十分な空き VRAM が必要です。 |
| **MLX** | Apple Siliconの互換モデル。 | MLX エンジンとサポートされているプラ​​ットフォーム。 |

ハブが固定されるようになりました **LFM3-1.7B** は、Q4_K_M、Q6_K、および Q8_0 バリアントとの互換性のある構成の LiquidAI 推奨事項です。最初に実行されるモデルは、上記のガイド付き構成にリストされているもののままです。

ダウンロードの重みを次からフィルタリングします **1 未満 GB ～ 500 GB 以上**、ハードウェアの適合性、サイズ、最新性、ダウンロード数で並べ替えます。結果は徐々に読み込まれます。フィルターは、取得されたモデルとそのデフォルトのバリアントに適用されます。メモリ アドバイスでは、共有 GPU メモリを二重にカウントすることなく、利用可能な RAM/VRAM、コンテキストおよびコンパニオン コンポーネントを使用します。

AWQ 4-bit、GPTQ 4-bit、NF4、および INT8 はそれぞれ、オフラインで作成された小さな未トレーニング モデルを使用して、RTX 5070 Laptop 上にテキストを生成しました。これは、すべてのモデルの品質やパフォーマンスではなく、読み込みと実行を検証します。 **これらの追加はソース内にあります。再構築と互換性のある依存関係が必要です。この README アップデートでは、インストールされているバイナリはアップグレードされません。**

**RTX 5070 Laptop で測定:** Qwen2.5-0.5B-Instruct、コンテキスト 2,048、プロンプト 272 トークン、128 生成されたトークン、5 つのウォームド実行: 中央デコード **GGUF Q4_K_M 402.7 tokens/s · EXL3 4 bpw 312.5 · EXL2 4 bpw 146.9**. この測定では GGUF に対する速度の優位性は確認できませんでした。量子化とキャリブレーションの条件が異なり、EXL3 は簡単な算術テストを一つ通過できませんでした。速度や品質の一般的な順位を示す結果ではありません。 [完全な測定値と制限値](deliverables/exllama-2026-10-30/validation.md).

**TabbyAPI** はオプションの個別に管理される OpenAI 互換のサーバー接続であり、デフォルトでは無効になっています。認証された EXL3 モデルの検出とストリーミングがテストされました。管理対象のローカル ExLlama ルートは別個のままです。 [ExLlama セットアップと TabbyAPI 接続](transformers-server/README.md#exl3-first-exl2-second--nvidia-execution).

デフォルトのハードウェアに適応した並べ替えでは、同じ互換性と使用可能なメモリ層内の新しいリリースが優先されます。インストールされているモデルは自動的に置き換えられません。

[クオンタイズ済み Safetensors セットアップ](transformers-server/README.md#quantized-safetensors--source-integration-29-october-2026) · [形式、優先順位、検証](docs/SUIVI_MOTEURS.md)

更新されたソースに追加 **Windows x64 の構成のオプションの管理対象コンポーネント**: プライベート Python 環境、固定された CPU/CUDA プロファイル、ダウンロード前の見積もりと確認、検証、修復、削除。カスタム インタープリタ パスは詳細オプションの下に残ります。ネイティブ GGUF エンジンは既存のコンポーネントを保持します。モバイルとクラウドはデスクトップ Python/PyTorch をダウンロードしません。 3 つのプライベート CPU/エクスポート プロファイルは、合成テストデータを使用して実行されました。メンテナは、2026年11月1日 でデスクトップの使用が成功したと報告しています。 GPU プロファイルとクリーン PC インストールには、別途詳細な検証が必要です。 [プロファイルとテスト限界](docs/REPRISE_COMPOSANTS_GERES_80_LANGUES.md)。 EXE へのスタックの埋め込みは延期されます。

## 104 インターフェース言語とそのバリアント

**すべての 104 カタログは、現在の 2,435 英語キーをカバーしています。** メニュー、構成、設定、ヘルプ、メディア コントロールを含む、15 名前空間全体。複数の形式とインターフェイスの方向は、選択した言語に従います。応答言語と音声言語はモデルによって異なります。

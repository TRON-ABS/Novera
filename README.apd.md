## Novera 1.0.1

Novera 1.0.1 متاح للأنظمة الأساسية المذكورة أدناه. قم بتنزيل الحزمة لنظامك أو استخدم قناة التحديث الموقعة الخاصة بها. يتم تحديث عمليات التثبيت الموجودة عند تثبيت الحزمة الجديدة أو قبول التحديث.

- الأمان: أذونات أصلية أكثر صرامة للصفحات البعيدة، ومصادقة واجهات برمجة تطبيقات الشبكة وأدوات الخادم، وتخزين وترحيل سري محمي، ووصول أكثر أمانًا إلى الملفات/الوسائط، وتحليل جداول البيانات، وإنشاء البرامج النصية. تم تحديث التبعيات المكشوفة؛ ويتم تتبع التحذيرات المتبقية بشكل علني.
- الخصوصية: تتطلب الإحصائيات وتقارير الأخطاء موافقة منفصلة وتظل معطلة بشكل افتراضي. تتضمن البنيات تكوين الوجهة الموثق. تتم تصفية التشخيص الفني. يحتفظ المستخدمون بالتحكم في التنشيط.
- المحرك المحلي: `llama.cpp v0.9.0` (`b12110`, `cd959bae99ff4bed22bef2604f45241c09bbb8c8`). إصدار المحرك وإصدار التطبيق منفصلان. تم تصحيح إعدادات النموذج الأولية وتسجيل النموذج/جهاز العرض، بما في ذلك فشل بدء التشغيل الذي يتضمن `kv_unified`. يتم الاحتفاظ بالإعدادات الشخصية الموجودة.
- اللغات: 24 لغات ومتغيرات إضافية تعمل على جلب الواجهة ومجموعة README المترجمة إلى 104، مع 2,435 مفاتيح واجهة لكل كتالوج. لا تصادق هذه التغطية على جودة التحرير الأصلية أو دعم الكلام في كل لغة.
- **LFM3-Omni-2B Q4_K_M** — دا الموديل الافتراضي للكمبيوتر والموبايل. نموذج صغير للنصوص والصور والصوت، يحتاج ملف `mmproj`. حجم تنزيل الملفين نحو 1.39 GB. مناسب لإعداد متعدد الوسائط أخف. ميزات الصوت تعتمد على المنصة والمحرك، والسياق الأطول يحتاج ذاكرة أكبر.
- **NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M** — دا بديل للنصوص. بديل نصي للمحادثة والكتابة والأدوات والإجابات المنظمة. التنزيل نحو 6.18 GB. يحتاج ذاكرة أكثر من LFM3-Omni ولا يعالج الصور أو الصوت بنفسه. قراءة الإجابات تستعمل صوت النظام. اختاره للمهام النصية إذا كانت الذاكرة كافية، وتحقق من المعلومات بمصادر.
- بالنسبة إلى 1.0.1، فإن LFM3-Omni-2B Q4_K_M مع `mmproj-LFM3-Omni-2B-Q4_K_M.gguf` المطلوب هو التوصية الافتراضية على سطح المكتب والجوال؛ يظل NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M بديلاً للنص فقط. السياق الأولي هو 32,768 من الرموز المميزة على سطح المكتب و2,048 على الهاتف المحمول. تستخدم السياقات الأطول المزيد من الذاكرة. يتم الاحتفاظ باختيارات وإعدادات النموذج الحالي حتى يتم تغييرها بشكل صريح.

## من أول تشغيل لغاية النتائج

**الأتمتة بتاعتنا بتربط التحضير بسير عمل التنفيذ الكامل.** Novera بيتعامل مع الخطوات التقنية المتاحة للإعداد المختار، مع إبقاء الضوابط المتقدمة متاحة.

| خطوة | إيه اللي بيتعامل معاه Novera |
| --- | --- |
| **1. ابدأ** | بيختار لغة نظام مدعومة عند أول تشغيل وبيحفظ تفضيلك. بيعرض نماذج بداية ومعلومات هاردوير مفيدة. |
| **2. تجهيز** | التنصيب الموجه بيقدّم نصوص، تضمينات، صور، موسيقى، فيديوهات وتكبير. بيعرض المكونات والأحجام والمساحة الفاضية قبل موافقتك، بعدين بيتابع التحميلات مع التقدم، إيقاف/استئناف، وتوثيق SHA-256. |
| **3. استرجاع وإعادة استخدام** | يسجّل النماذج ومكوناتها، ويجهّز الملفات الشخصية والتقارير للتبعيات المطلوبة. تبدأ تضمينات الاسترجاع على CPU مع اختيار محفوظ CPU/GPU. ملفات الموسيقى الجديدة تكون افتراضياً في وضع الآلات الموسيقية. |
| **4. افهم الطلب** | المحركات والتحقق |
| **5. نفّذ** | الذاكرة الأوتوماتيكية بتستنى الشغل النشط، بتفرّغ النماذج غير الضرورية وبتعيد تحميل الموارد المطلوبة. سلسلة شغل 1–10 بتشتغل بالترتيب وبتفرّغ الموارد قبل الشغل الجاي. مزوّدي السحابة بيستخدموا الحساب والإعدادات المختارة. |
| **6. استرجاع وإعادة استخدام** | بيحفظ الميديا في مجلدات نظام Novera، بيورّي النتائج والأوقات المتاحة، بعدين بيقدّم خيارات: المتغيرات، المكتبة، النسخ، التصدير، أو المشاركة بالنظام. الإرسال لتطبيق تاني بيبقى تصرفك أنت. |

الأتمتة بتشمل المحركات المتكاملة وسير العمل؛ ما بتخلي كل موديل Hub قابل للتنفيذ. الهاردوير، والمكونات المثبتة، ووصول المزود بتحدد شنو ممكن يشتغل. المجلدات، وتغييرات الملفات، وأوامر الشل بتتبع تصاريح الوصول للمحادثة.

[دليل المستخدم](docs/USER_GUIDE.md) · [محركات والتحقق](docs/SUIVI_MOTEURS.md) · [بيوجّه تلقائياً طلبات الإنشاء المعترف بيها للنص، الصورة، الموسيقى أو الفيديو. ممكن كمان تختار بوضوح وضع الإخراج ونموذج محلي أو سحابي.](docs/DEVELOPMENT.md)

| **استرجاع المستندات** | **Qwen3-Embedding-0.6B Q8_0**, **CPU افتراضياً**، مع اختيار CPU/GPU محفوظ. |
| **صورة** | **FLUX.2 Klein 4B Q4_K_M**, **Qwen3-4B Q4_K_M** مُشفِّر و FLUX.2 الرسمي VAE. |

## المركز والنماذج المتوافقة

**GGUF، و Safetensors القياسي والمكمّم، و ONNX، و MLX**: استكشف النماذج حسب المهمة واختار المتغيرات المتوافقة مع المحرك ومعداتك.

| عائلة | الدعم في المصدر | الإعدادات، والمُجزّئ (tokenizer)، وكل جزء مطلوب. |
| --- | --- | --- |
| **GGUF** | توليد نصوص عن طريق llama.cpp؛ ومكونات صور وفيديو للملفات المدعومة. | مجلد كامل مُصادق عليه؛ يتطلب معالجة مسبقة/لاحقة خاصة بالمهمة؛ |
| **قسّم GGUF** | نسخة واحدة لكل سلسلة كاملة، الحجم المجموع، تحميل جميع الأجزاء، وفحص الحجم/SHA-256/رؤوس البيانات | أسماء ملفات مرقمة قياسية؛ تحميل 500 GB ما بيعني إن النموذج بيناسب هذا PC. |
| **قياسي Safetensors** | إكمّل المجلدات عن طريق Transformers، والنص السببي على CPU أو NVIDIA CUDA. | المتطلبات |
| **ONNX Runtime** | نص عن طريق GenAI؛ ومكونات صور/فيديو للملفات الشخصية المدعومة. | بنية معمارية معترف بها من قبل المحرك المدمج. [إعدادات وحدود](onnx-server/README.md). |
| **LoRA / PEFT محولات** | استيراد قاعدة كاملة مع المحول المحلي المنفصل بتاعها في مزود Safetensors | قاعدة Transformers السببية غير المُكمّمة، مطابقة للهوية، وفحوصات التنسور وتقدير الذاكرة التراكمي؛ [إعدادات وحدود](transformers-server/README.md#local-lora--peft-adapters). |
| **FP8 LLM / ModelOpt** | تنفيذ CUDA الأصلي لـ Llama/Qwen2/Qwen3 الكثيف المتوافق وتصديرات FP8 لكل تنسور. | فحوصات المعمارية/التنسور ومسبار النواة الحقيقي؛ [إعدادات وحدود](transformers-server/README.md#modelopt-fp8-and-nvfp4-llms). |
| **NVFP4 LLM / ModelOpt** | إسقاطات الكتلة المعبأة-16 FP4 عبر GEMMs الأصلية لـ CUDA؛ منفصل عن صورة NVFP4. | Blackwell GPU المتوافق، الأبعاد/التصدير المدعومة ومسبار النواة الفعلي؛ تم اختبار نماذج الاختبار غير المُدرّبة على RTX 5070. |
| **AWQ** | نقاط تفتيش نموذج GEMM بـ 4-بت بدون دمج العمليات. | محمّلات NVIDIA CUDA و GPTQModel/Transformers الاختيارية. |
| **GPTQ** | تكوينات 2/3/4/8-بت، صيغ gptq/gptq_v2. | NVIDIA CUDA، GPTQModel و Optimum؛ تم اختبار التنفيذ الحقيقي عند بتات 4. |
| **bitsandbytes** | 4-بت NF4/FP4 أو 8-بت INT8. | فحوصات NF4 و INT8 الحقيقية مع NVIDIA CUDA والتبعيات الاختيارية؛ |
| **EXL3** | مجلدات نموذج Safetensors المُكمَّمة بالكامل اتحمّلت عن طريق ExLlamaV3؛ تم اختبار التوليد الفعلي باستخدام CUDA. | NVIDIA GPU، بيئة Python 3.12 منفصلة ومعمارية متوافقة؛ ما في رجوع لـ CPU. |
| **EXL2** | محمّل مخصص لـ ExLlamaV2؛ تم اختبار البث، والإلغاء، والتفريغ على GPU. | لازم تختار CUDA Attention backend بوضوح للبيئة البرمجية المختبرة؛ مطلوب checkpoint كامل للموديل وذاكرة VRAM متاحة كافية. |
| **MLX** | نماذج متوافقة على Apple Silicon. | محرك MLX والمنصة المدعومة. |

الـ Hub بيثبّت توا الآن. **LFM3-1.7B** كم نصيحة LiquidAI للتكوينات المتوافقة، مع متغيرات Q4_K_M و Q6_K و Q8_0. النموذج الأول اللي بيشتغل بيضل هو المذكور في التكوين الموجه فوق.

فلترة أوزان التحميل من **تحت 1 GB لـ 500 GB وما فوق**, بعدين ترتيب حسب توافق الهاردوير، الحجم، الحداثة، أو التحميلات. النتائج بتتحمّل تدريجياً؛ الفلاتر بتنطبق على النماذج المُسترجعة ومتغيرها الافتراضي. نصيحة الذاكرة بتستخدم RAM/VRAM المتاح، والسياق والمكونات المرافقة، بدون عد مضاعف لذاكرة GPU المشتركة.

AWQ 4-bit، GPTQ 4-bit، NF4 و INT8 كل واحد بيولّد نص على RTX 5070 Laptop باستخدام نماذج صغيرة غير مُدرّبة مُنشأة أوفلاين. ده بيصادق على التحميل والتنفيذ، مش جودة أو أداء كل نموذج. **الإضافات دي موجودة في المصدر: مطلوب إعادة بناء واعتماديات متوافقة؛ تحديث README ده ما بيحدّث باينري مُثبّت.**

**مُقاس على RTX 5070 Laptop:** Qwen2.5-0.5B-Instruct، سياق 2,048، رموز موجه 272، رموز مُولّدة 128، خمس تشغيلات مُدفّأة: وسيط سرعة توليد الرموز **GGUF Q4_K_M 402.7 tokens/s · EXL3 4 bpw 312.5 · EXL2 4 bpw 146.9**. ما تم إثبات أي فائدة في السرعة مقارنة بـ GGUF هنا. التكميم/المعايرة مختلف، و EXL3 فشل في اختبار حساب بسيط واحد؛ النتائج دي مش تصنيف عام للسرعة أو الجودة. [القياسات والحدود الكاملة](deliverables/exllama-2026-10-30/validation.md).

**TabbyAPI** هو اتصال خادم اختياري ومُدار بشكل منفصل ومتوافق مع OpenAI، ومُعطّل افتراضياً. تم اختبار اكتشاف وتدفق نموذج EXL3 الموثق. المسار المحلي المُدار ExLlama بيضل منفصل. [تجهيز ExLlama واتصال TabbyAPI](transformers-server/README.md#exl3-first-exl2-second--nvidia-execution).

الترتيب الافتراضي المتكيف مع الهاردوير بيفضّل الإصدارات الأحدث ضمن نفس مستوى التوافق والذاكرة المتاحة. النماذج المثبتة ما بتتغير تلقائياً.

[تجهيز Safetensors المُكمَّم](transformers-server/README.md#quantized-safetensors--source-integration-29-october-2026) · [التنسيقات، الأولويات، والمصادقة](docs/SUIVI_MOTEURS.md)

المصادر المُحدّثة بتضيف **مكونات مُدارة اختيارية في الإعدادات لـ Windows x64**: بيئات بايثون خاصة، ملفات تعريف CPU/CUDA مثبتة، تقديرات وتأكيد قبل التنزيل، تحقق، إصلاح وإزالة. مسارات المفسر المخصصة تظل تحت الخيارات المتقدمة. محركات GGUF الأصلية تحتفظ بمكوناتها الحالية؛ الجوال والسحابة لا يقومون بتنزيل بايثون المكتبي/PyTorch. تم اختبار ثلاثة ملفات تعريف خاصة CPU/تصدير ببيانات اختبار اصطناعية؛ يبلغ المسؤول عن صيانة المشروع عن استخدام مكتبي ناجح على 1 نوفمبر 2026؛ ملفات تعريف GPU وتثبيت clean-PC لا تزال بحاجة إلى تحقق منفصل ومفصل. [ملفات التعريف وحدود الاختبار](docs/REPRISE_COMPOSANTS_GERES_80_LANGUES.md). تأجيل تضمين المكدس في EXE.

| فنون، ثقافة، إعلام، لغات وتراث | ادعم الكتابة، الترجمة، الصور، الفيديو، المشاريع الإبداعية والمشاركة الثقافية. |
| النقل، اللوجستيات، السياحة، الرياضة وحياة المجتمع | مساعدة في التخطيط، التواصل، التعلم والمبادرات المحلية. |
| سياسة الإصدار الرسمية | صفحة الإصدارات |

. المرشحين الموجودين اللي ما عندهم مُحدّث بيضلوا داخليين. الإصدارات العامة بتتطلب آلية تحديث مُهيّأة ومُصادق عليها؛

## فحوصات التوقيع على سطح المكتب ومتطلبات التشغيل المتبقية موثقة

الصورة المعروضة بتورّي تطبيق Windows مجمّع محلياً من قِبل المُصيِن. تغييرات المصدر، والاختبارات المُستهدفة، وتوثيق العتاد مُوثّقين بشكل منفصل؛ ده ما بيوثّق كل موديل، أو منصة، أو حساب سحابة.

التجميعات اليدوية لـ GitHub Actions مُمكّنة لكل الـ 11 نوع توزيع. اتبع [القواعد الذهبية لمعلومات المنتج والمستخدم (بالفرنسي)](docs/CI_DISTRIBUTIONS.md)الموديلات والمحركات [الوصول، العمل الإنساني والحياة اليومية](OFFICIAL_RELEASES.md) و [تقليل حواجز اللغة والمعرفة ودعم الناس بمساعدة عملية.](https://github.com/TRON-ABS/Novera/releases)دي توجيهات للمساهمة والتطوير، ما هي ادعاء إن كل تطبيق خاص بمجال معين تم تسليمه أو تصديقه خلاص. نحب توجيه بسيط للاستخدام اليومي، خيارات متقدمة واضحة وقت الحاجة، متطلبات شفافة للأجهزة والسحابة، وتعاون مع الناس اللي عارفين كل مجال والسياق المحلي.

## 從首次啟動到結果

**我們的自動化將準備工作與完整的執行工作流程連結。** Novera 處理所選配置可用的技術步驟，同時保持高階控制的可存取性。

| 步驟 | 箇Novera處理 |
| --- | --- |
| **1. 開始** | 在首次啟動時選擇支援的系統語言並儲存您的首選項。提供起始模型和有用的硬體資訊。 |
| **2. 準備** | 引導式安裝提供文字、嵌入、圖像、音樂、影片和升級。它會在您批准之前預覽元件、大小和可用空間，然後追蹤下載進度、暫停/恢復和 SHA-256 驗證。 |
| **3. 設定** | 註冊模型及其元件，準備相關設定檔並報告所需的依賴關係。檢索嵌入從 CPU 開始，並儲存 CPU/GPU 選擇。新的音樂配置預設為樂器模式。 |
| **4. 拕要求** | 自動將辨識的建立請求路由到文字、圖像、音樂或影片。您也可以明確選擇輸出模式以及本機或雲端模型。 |
| **5. 執行** | 自動記憶體等待活動工作，釋放不需要的模型並重新載入所需的資源。 1–10 作業系列依序運行，並在下一個作業之前釋放資源。雲端提供者使用選定的帳戶和配置。 |
| **6. 擷取並重用** | 將媒體保存在 Novera 系統資料夾中，顯示結果和可用計時，然後提供變體、庫、複製、匯出或系統共用。發送到另一個應用程式仍然是您的操作。 |

自動化涵蓋整合引擎和工作流程；它並不會使每個 Hub 模型都可執行。硬體、安裝的元件和提供者存取權限決定了哪些內容可以運作。資料夾、檔案變更和 shell 指令遵循對話的存取授權。

## 來源裏嗰能力

| 區域 | 功能 |
| --- | --- |
| **文字和視覺** | 對話、文件附件、串流回應以及本地或雲端模型。願景取決於型號；理解和生成圖像是不同的能力。 |
| **圖像** | 對話中產生、種子、比率、解析度、GGUF/Safetensors 元件、設定的 Diffusers 資料夾和支援的本機 NVFP4 CUDA 設定檔。 |
| **音樂** | 本地或雲端生成、持續時間、品質、樂器或人聲（如果支援）、結構化歌詞和音訊播放器。提供者的選擇有所不同。 |
| **影片** | 本地或雲端生成、持續時間、本地設定檔的幀數/節奏、比率、解析度和視訊播放器。 |
| **搜尋和工具** | Web 搜尋、基於嵌入的文件檢索、MCP、工作區和本機工具（根據模型支援和授予的存取權限）。 |
| **結果和分享** | 媒體庫、變體、回應/對話匯出、文件和原始媒體、列印/PDF 以及依賴平臺的系統共用。 |
| **資源管理** | 預設啟用自動內存，支援組件的 CPU/GPU 設置，以及資源允許時的手動設定檔。 |

## 集線器及相容型號

**GGUF、標準與量化 Safetensors、ONNX 和 MLX**：依任務探索模型並選擇與引擎和硬體相容的變體。

| 家庭 | 源碼支持 | 要求 |
| --- | --- | --- |
| **GGUF** | 透過llama.cpp產生文字；支援的設定檔的圖像和視訊組件。 | 捆綁引擎識別的架構。 |
| **分割 GGUF** | 每個完整系列一個變體、總大小、全分片下載和大小/SHA-256/標頭檢查。 | 標準編號檔名；下載 500 GB 並不代表此型號適合此 PC. |
| **標準 Safetensors** | 透過 Transformers 完成資料夾，CPU 或 NVIDIA CUDA 上的因果文字。 | 配置、標記器和每個所需的分片。 |
| **ONNX Runtime** | 本地匯入數字/布林圖並準備 GenAI 文字匯出。 | 已驗證的完整資料夾；需要特定於任務的預處理/後處理； [設定與限制](onnx-server/README.md). |
| **LoRA / PEFT 適配器** | 在 Safetensors 提供者中匯入完整的基礎及其單獨的本機適配器。 | 未量化因果 Transformers 基數、匹配身分、張量檢查和累積記憶體估計； [設定與限制](transformers-server/README.md#local-lora--peft-adapters). |
| **FP8 LLM / ModelOpt** | 原生 CUDA 執行，用於相容於密集 Llama/Qwen2/Qwen3 每個張量 FP8 導出。 | 架構/張量檢查和真實內核探測； [設定與限制](transformers-server/README.md#modelopt-fp8-and-nvfp4-llms). |
| **NVFP4 LLM / ModelOpt** | 打包塊-16 FP4 透過原生 CUDA GEMM 投影；與影像 NVFP4 分開。 | 兼容 Blackwell GPU，支持的維度/導出和實際內核探測；未訓練的測試模型在 RTX 5070 上測試。 |
| **AWQ** | 未融合 4-bit GEMM 檢查點。 | NVIDIA CUDA 和可選 GPTQModel/Transformers 加載器。 |
| **GPTQ** | 2/3/4/8-bit 配置，gptq/gptq_v2 格式。 | NVIDIA CUDA、GPTQModel 和 Optimum；實際執行在 4 位元進行測試。 |
| **bitsandbytes** | 4-bit NF4/FP4 或 8-bit INT8. | NVIDIA CUDA 和可選依賴；真實的 NF4 和 INT8 測試。 |
| **EXL3** | 透過ExLlamaV3加載的完整量化Safetensors模型資料夾；使用 CUDA 的實際生成進行了測試。 | NVIDIA GPU，獨立的Python 3.12環境和相容架構；沒有 CPU 後備。 |
| **EXL2** | 專用ExLlamaV2裝載機；在 GPU. 上進行串流、取消和卸載測試 | 明確選擇測試軟件棧的 CUDA 注意力後端；需要完整的模型檢查點和足夠的可用 VRAM。 |
| **MLX** | 在 Apple Silicon 上的兼容模型。 | MLX 引擎和支持的平臺。 |

Hub 現已鎖定 **LFM3-1.7B** 作為其相容配置的 LiquidAI 推薦，具有 Q4_K_M、Q6_K 和 Q8_0 變體。首次運行的模型仍然是上面指導配置中列出的模型。

從過濾下載權重 **在 1 GB 下至 500 GB 及以上**，然後依硬體適合度、大小、新近度或下載次數排序。結果逐漸載入；過濾器適用於所取得的模型及其預設變體。記憶體建議使用可用的 RAM/VRAM、上下文和配套元件，而不重複計算共享 GPU 記憶體。

AWQ 4 位元、GPTQ 4 位元、NF4 和 INT8 皆使用離線建立的未經訓練的微型模型在 RTX 5070 Laptop 上產生文字。這驗證了載入和執行，而不是每個模型的品質或效能。 **這些補充在原始碼中：需要重建和相容依賴；此 README 更新不會升級已安裝的二進位。**

**測量箇 RTX 5070 Laptop:** Qwen2.5-0.5B-Instruct，上下文 2,048，提示 272 令牌，128 產生的令牌，五次預熱運行：中位數解碼 **GGUF Q4_K_M 402.7 tokens/s · EXL3 4 bpw 312.5 · EXL2 4 bpw 146.9**。 箇冇比 GGUF 快箇益處。 量化/校準唔同，箇 EXL3 冇過基本算術檢測；箇結果唔係一般速度或品質排名。 [完整測量和限制](deliverables/exllama-2026-10-30/validation.md).

**TabbyAPI** 是可選的、單獨管理的 OpenAI 相容伺服器連接，預設為停用。測試了經過身份驗證的 EXL3 模型發現和串流媒體。受管理的本地 ExLlama 路由仍然不同。 [ExLlama 設定和 TabbyAPI 連接](transformers-server/README.md#exl3-first-exl2-second--nvidia-execution).

預設的硬體適應排序有利於相同相容性和可用記憶體層中的較新版本。已安裝的模型不會自動替換。

[量化 Safetensors 設定](transformers-server/README.md#quantized-safetensors--source-integration-29-october-2026) · [格式、優先級和驗證](docs/SUIVI_MOTEURS.md)

更新的來源增加 **箇 Windows x64 設定中可選管理元件**: 私有 Python 環境、鎖定 CPU/CUDA 設定檔、下載前估算和確認、驗證、修復和移除。 自定義解釋器路徑留喺進階選項下。 原生 GGUF 引擎保留原有元件；行動和雲端冇下載桌面 Python/PyTorch。 測試箇三個私有 CPU/導出設定檔使用合成測試數據；維護者報告箇 1 十一月 2026 箇 GPU 設定檔和乾淨-PC 安裝仍需單獨、詳細驗證。 [設定檔和測試限制](docs/REPRISE_COMPOSANTS_GERES_80_LANGUES.md)。 箇元件包到 EXE 吥推遲。

## 120 介面語言與變體

原始碼更新， 6 十一月 2026: 24 額外的介面目錄使總數達到 104。這些是輔助翻譯草稿；本地審查和區域適應仍然是必要的。這批准備目錄和翻譯的自述文件；需要重建應用程式才能將它們包含在已安裝的二進位檔案中。

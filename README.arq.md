ف الماك، افتح DMG و نسخ Novera لداخل Applications. إذا أول تشغيل تْحْبَس، سمح لـ Novera في **إعدادات النظام → الخصوصية والأمان → فتح على أي حال**. [تعليمات آبل](https://support.apple.com/guide/mac-help/mh40616/mac).

توقيعات التحديث ماشي تاع Windows Authenticode ولا توثيق آبل. الفحوصات اليدوية تاع الإصدار الحالي تنجح مع القناة العامة؛ الانتقال بين إصدارين عامين يبقى اختبار للإصدار الجاي. [الأدلة والقيود](docs/LAUNCH_STATUS.md).

على Android، يوصى بهاتف مودرن بذاكرة كافية للموديلات المحلية؛ استعمل موفر API في الأجهزة الأضعف. للبحث في الويب، سياق على الأقل **رموز 16K (16,384)** يوصى به، باستمرار عبر الإصدارات.

**Windows x64 محمول 1.0.0 متوفر.** النقاشات، الإعدادات والموديلات اللي تْحْمّل تبقى لداخل المجلد المحمول تحت `Data`. استخرج الأرشيف الكامل وابدا `Novera.exe`. سد Novera قبل ما تحرك المجلد ولا تْفصل تخزين USB. [دليل ومحددات المحمول](docs/WINDOWS_PORTABLE.md).

## لوحة تحكم وحدة لكل إنشاء

Novera يكبر معاك. الأمثلة والإعدادات تاعك يقدروا يساعدوا مستخدمين آخرين يلقاو إعداد مناسب. شارك الأسئلة، المشاكل والأفكار تاعنا في [صفحة Facebook](https://www.facebook.com/profile.php?id=61596114515071) ولا عن طريق [إيميل](mailto:contact.novera.tronabs@gmail.com). إذا ممكن، حط إصدار Novera تاعك، الجهاز والموديل المحلي/API. نحي المعلومات الشخصية وما تشاركش أبدًا مفاتيح أو كلمات مرور API.

![صورة مولدة بواسطة Novera ولوحة تحكم موحدة مع الكمية، البذرة، التكبير التلقائي والذاكرة التلقائية](.github/assets/novera-dashboard-2026-11-01.png)

*لقطة شاشة حقيقية لتطبيق Windows قدمها المسؤول على 1 نوفمبر 2026، الذي أفاد بأن التطبيق يعمل جيداً. يظهر مشهداً مُولداً، وأدوات حفظ الملفات، ولوحة تحكم الإنشاء الموحدة؛ هذا ليس نموذجاً وهمياً.*

لوحة واحدة، خمس أوضاع: **تلقائي / نص / الصورة / موسيقى / فيديو**. تتبع الأدوات الوضع المختار: النسبة، الدقة، المدة، الإيقاع، الجودة، الآلات الموسيقية، الكلمات، البذرة والكمية. يتكيف عرض اللوحة والأزرار مع النافذة والتسميات المترجمة.

- **توليدات متسلسلة 1–10**, افتراضياً 1، مع كميات مستقلة للصورة والموسيقى والفيديو. الإيقاف يلغي المهمة النشطة والطابور المتبقي.
- **عشوائية، ثابتة، +1 و −1 بذور**, نسب محددة مسبقاً أو مخصصة واختياري **Real-ESRGAN ×2/×4** تكبير مع عرض الأبعاد النهائية.
- النموذج المختار، الذاكرة التلقائية، المرفقات، التعليمات، البحث عبر الويب والأدوات تبقى في نفس الشريط. تعتمد الأدوات على قدرات النموذج والصلاحيات الممنوحة.

## من أول تشغيل إلى النتائج

**الأتمتة تاعنا تربط التحضير بسير عمل التنفيذ الكامل.** Novera يتعامل مع الخطوات التقنية المتاحة للتكوين المختار، مع إبقاء الضوابط المتقدمة متاحة.

| خطوة | واش يتعامل معاه Novera |
| --- | --- |
| **1. ابدأ** | يختار لغة نظام مدعومة عند التشغيل الأول ويحفظ تفضيلك. يعرض النماذج الأولية ومعلومات الأجهزة المفيدة. |
| **2. تحضير** | التثبيت الموجه يقدم نصوص، تضمينات، صور، موسيقى، فيديو وتكبير. يعرض المكونات والأحجام والمساحة الحرة قبل موافقتك، ثم يتتبع التنزيلات مع التقدم، الإيقاف/الاستئناف وSHA-256 تحقق. |
| **3. استرجاع وإعادة استخدام** | يسجل الموديلات ومكوناتها، يجهز البروفايلات والتقارير اللازمة والتبعيات المطلوبة. تبدأ التضمينات الاسترجاعية على CPU مع اختيار محفوظ CPU/GPU. بروفايلات الموسيقى الجديدة تكون افتراضياً في وضع الآلات الموسيقية. |
| **4. فهم الطلب** | المحركات والتحقق |
| **5. نفّذ** | الذاكرة الأوتوماتيكية تسنى الخدمة النشطة، تحرر النماذج غير الضرورية وتعيد تحميل الموارد المطلوبة. سلسلة مهام 1–10 تخدم بالترتيب وتحرر الموارد قبل المهمة الجاية. مزودو السحابة يستعملو الحساب والتكوين المختارين. |
| **6. يجيب ويعاود يستعمل** | يخزن الوسائط في مجلدات نظام Novera، يعرض النتائج والأوقات المتاحة، ومن بعد يعرض خيارات (النسخ، المكتبة، النسخ، التصدير، أو المشاركة بالنظام). الإرسال لتطبيق آخر يبقى قرارك. |

الأتمتة تغطي المحركات والتدفقات المتكاملة؛ ما تخليش كل موديل تاع Hub قابل للتنفيذ. الهاردوير، المكونات المثبتة، ووصول المزوّد يحددو واش يقدر يخدم. المجلدات، تغييرات الملفات، وأوامر الشل يتبعو صلاحيات الوصول تاع المحادثة.

[دليل المستخدم](docs/USER_GUIDE.md) · [محركات والتحقق](docs/SUIVI_MOTEURS.md) · [يوجّه الطلبات الإبداعية المعترف بها تلقائيًا إلى نص، صورة، موسيقى أو فيديو. يمكنك أيضًا تحديد وضع الإخراج صراحةً ونموذج محلي أو سحابي.](docs/DEVELOPMENT.md)

في المصادر المحدّثة، **التكوينات تتكيف مع التوصيات تاعها للموبايل وللأجهزة اللي فيها قيود**: LFM3-1.7B Q4, ولا LFM3-Omni-2B Q4 مع البروجيكتور تاعو كي يتوفروا متطلبات الذاكرة والمحرك المذكورة. التوليد المحلي غير المتوفر مخبي ولا محظور؛ الصورة والموسيقى والفيديو السحابية المكونة تبقى متوفرة. توجيه الواجهة يعاود يستعمل كتالوجات لغة 80. هاد التقديرات مازالو يحتاجو اختبار الجهاز وإعادة بناء باش يوصلو للتطبيقات المثبتة.

## الهب والنماذج المتوافقة

**GGUF، و Safetensors القياسي والمكمم، و ONNX، و MLX**: شوف الموديلات حسب المهمة واختار الأنواع المتوافقة مع الموطور (engine) و الهاردوير تاعك.

| العائلة | الدعم في المصدر | المتطلبات |
| --- | --- | --- |
| **GGUF** | توليد نصوص عبر llama.cpp؛ مكونات صور وفيديو للحسابات المدعومة. | بنية معمارية معترف بها من طرف الموطور المضمّن. |

| **Safetensors القياسي** | ملفات كاملة عبر Transformers، نص سببي (causal text) على CPU ولا NVIDIA CUDA. | التكوين (Configuration)، المرمز (tokenizer) وكل شارد (shard) مطلوب. |
| **ONNX Runtime** | استيراد محلي للرسوم البيانية الرقمية/المنطقية (bool) وتصديرات النص المُجهزة لـ GenAI. | ملف كامل مُصادق عليه؛ يتطلب معالجة مسبقة/لاحقة خاصة بالمهمة؛ [الإعداد والحدود](onnx-server/README.md). |
| **مُكيّفات (adapters) LoRA / PEFT** | استورد قاعدة كاملة مع المُكيّف المحلي المنفصل تاعها في مُزوّد Safetensors. | قاعدة Transformers سببية غير مُكمّاة، تطابق الهوية، فحوصات الموترات وتقدير الذاكرة التراكمي؛ [الإعداد والحدود](transformers-server/README.md#local-lora--peft-adapters). |
| **FP8 LLM / ModelOpt** | تنفيذ أصلي لـ CUDA للتصديرات FP8 لكل موتر من Llama/Qwen2/Qwen3 الكثيف المتوافق. | فحوصات المعمارية/الموترات واستقصاء النواة الحقيقي؛ [الإعداد والحدود](transformers-server/README.md#modelopt-fp8-and-nvfp4-llms). |
| **NVFP4 LLM / ModelOpt** | إسقاطات FP4 كتلة مُعبأة-16 عبر GEMMs الأصلية لـ CUDA؛ منفصل عن صورة NVFP4. | Blackwell GPU متوافق، أبعاد/تصدير مدعومة واستقصاء نواة حقيقي؛ اختبار نماذج اختبار غير مُدرّبة على RTX 5070. |
| **AWQ** | نقاط تفتيش نموذج 4-bit GEMM بلا دمج العمليات. | مُحمّلات NVIDIA CUDA واختيارية GPTQModel/Transformers. |
| **GPTQ** | تكوينات 2/3/4/8-bit، صيغ gptq/gptq_v2. | NVIDIA CUDA، GPTQModel و Optimum؛ تنفيذ حقيقي مُختبَر عند بتات 4. |
| **bitsandbytes** | 4-bit NF4/FP4 أو 8-bit INT8. | NVIDIA CUDA واعتماديات اختيارية؛ اختبارات حقيقية لـ NF4 و INT8. |
| **EXL3** | مجلدات موديل Safetensors الكمّي كامل تم تحميلها عبر ExLlamaV3؛ تم اختبار التوليد الفعلي مع CUDA. | NVIDIA GPU، بيئة Python 3.12 منفصلة ومعمارية متوافقة؛ لا يوجد تراجع CPU. |
| **EXL2** | مُحمّل ExLlamaV2 مُخصص؛ اختبار البث، الإلغاء والتفريغ على GPU.. | لازم تختار CUDA Attention backend بوضوح للبيئة البرمجية المختبرة؛ مطلوب checkpoint كامل للموديل وذاكرة VRAM متاحة كافية. |
| **MLX** | نماذج متوافقة على Apple Silicon. | محرك MLX والمنصة المدعومة. |

المركز (The Hub) يثبّت الآن. **LFM3-1.7B** كيما توصية LiquidAI تاعو للتكوينات المتوافقة، مع متغيرات Q4_K_M و Q6_K و Q8_0. الموديل تاع أول تشغيل يبقى هو اللي مكتوب في التكوين الموجه فوق.

صفي أوزان التنزيل من **تحت 1 GB حتى لـ 500 GB وفوق**, ومن بعد رتب حسب ملاءمة الهاردوير، الحجم، الحداثة ولا التنزيلات. النتائج تتحمل تدريجياً؛ الفلاتر تطبق على الموديلات اللي تتبعت وعلى المتغير الافتراضي تاعها. نصيحة الذاكرة تستعمل RAM/VRAM، السياق والمكونات المرافقة المتوفرة، بلا ما تحسب الذاكرة المشتركة GPU زوج مرات.

AWQ 4-bit، GPTQ 4-bit، NF4 و INT8 كل واحد يولد نص على RTX 5070 Laptop باستعمال موديلات صغيرة غير مدربة مصنوعة أوفلاين. هذا يثبت التحميل والتنفيذ، ماشي جودة ولا أداء كل موديل. **هذي الإضافات راهي في المصدر: لازم إعادة بناء وتوابع متوافقة؛ تحديث README هذا ما يحدّثش بايناري (ملف تنفيذي) مُثبّت.**

**مقيس على RTX 5070 Laptop:** Qwen2.5-0.5B-Instruct، سياق 2,048، توكنات البرومبت 272، توكنات مُولّدة 128، خمسة تشغيلات مُدفّئات: وسيط سرعة توليد التوكنات **GGUF Q4_K_M 402.7 tokens/s · EXL3 4 bpw 312.5 · EXL2 4 bpw 146.9**. ما تبيّن حتى فائدة في السرعة مقارنة بـ GGUF هنا. التكميم/المعايرة يختلف، و EXL3 فشل في اختبار حساب بسيط واحد؛ هذي النتائج ماشي تصنيف عام للسرعة ولا الجودة. [القياسات الكاملة والحدود](deliverables/exllama-2026-10-30/validation.md).

**TabbyAPI** هو اتصال خادم اختياري، مُدار بشكل منفصل ومتوافق مع OpenAI، معطّل بالافتراضي. تم اختبار اكتشاف وتدفق موديل EXL3 الموثّق. المسار المحلي المُدار ExLlama يبقى منفصل. [إعداد ExLlama واتصال TabbyAPI](transformers-server/README.md#exl3-first-exl2-second--nvidia-execution).

الترتيب الافتراضي المُكيّف مع الهاردوير يفضّل الإصدارات الأحدث ضمن نفس مستوى التوافق والذاكرة المتوفرة. الموديلات المثبتة ما يتجددوش أوتوماتيكياً.

[إعداد Safetensors المُكمّم](transformers-server/README.md#quantized-safetensors--source-integration-29-october-2026) · [التنسيقات، الأولويات، والتحقق](docs/SUIVI_MOTEURS.md)

المصادر المُحدّثة تزيد **مكونات مُدارة اختيارية في الإعدادات لـ Windows x64**: بيئات بايثون خاصة، ملفات تعريف CPU/CUDA مثبتة، تقديرات وتأكيد قبل التنزيلات، تحقق، إصلاح وإزالة. مسارات المفسر المخصصة تبقى تحت الخيارات المتقدمة. محركات GGUF الأصلية تحتفظ بمكوناتها الحالية؛ الجوال والسحابة لا يقومون بتنزيل بايثون المكتبي/PyTorch. تم اختبار ثلاثة ملفات تعريف خاصة CPU/تصدير ببيانات اختبار اصطناعية؛ يبلغ المسؤول عن الصيانة عن استخدام مكتبي ناجح على 1 نوفمبر 2026؛ ملفات تعريف GPU وتثبيت clean-PC لا يزالان بحاجة إلى تحقق منفصل ومفصل. [ملفات التعريف وحدود الاختبار](docs/REPRISE_COMPOSANTS_GERES_80_LANGUES.md). دمج الحزمة في EXE مؤجل.

## لغات ونسخ واجهة 80

**جميع كتالوجات 80 تغطي مفاتيح 2,429 الإنجليزية الحالية** عبر مساحات أسماء 15، بما في ذلك القوائم، والإعدادات، والتكوينات، والمساعدة، وعناصر التحكم في الوسائط. صيغ الجمع واتجاه الواجهة يتبع اللغة المختارة. تعتمد لغات الاستجابة والصوت بشكل منفصل على النموذج.

هذا التغطية التقنية لا تشهد على الجودة اللغوية: **المراجعة الأصلية والتكيف الإقليمي لا يزالان ضروريين**. انظر التسميات الأصلية والحدود المعروفة في [دليل اللغة](docs/LANGUAGES.md) و [تقرير التدقيق](deliverables/interface-audit-2026-10-29/RAPPORT.md).

## مساعدة الناس، في كل قطاع

أبعد من المدرسة والتعليم، طموحنا هو مساعدة الناس على التعلم وحل المشكلات وإنشاء وتطوير مشاريع مفيدة في جميع أنحاء العالم. يهدف Novera إلى جعل التطورات الحالية لـ AI أسهل في الفهم والاستخدام، عبر اللغات ومستويات الخبرة والأجهزة المتاحة.

| الخدمات العمومية، القانون والمشاركة المدنية | نسهل فهم الوثائق والإجراءات ونجعل الوصول للمعلومات أسهل. |
| الحوسبة، الأمن السيبراني، الروبوتات والاتصالات السلكية واللاسلكية | نساعد في تطوير البرمجيات، فهم الأنظمة وبناء أدوات مفيدة. |

هادو توجيهات للمساهمة والتطوير، ماشي ادعاء بلي كل تطبيق خاص بقطاع معين تْقدّم ولا تْتحقق. نحبو توجيه بسيط للاستعمال اليومي، خيارات متقدمة واضحة كي نحتاجو، متطلبات واضحة للعتاد والسحابة، وتعاون مع الناس اللي يعرفو كل مجال والسياق المحلي.

## حالة المشروع

**Novera 1.0.0 متوفر لـ Windows، Linux، macOS و Android.** لقطة الشاشة تبين تطبيق Windows مْجمّع محلياً من طرف المُحافظ. تغييرات المصدر، الاختبارات المستهدفة والتحقق من العتاد موثقة بشكل منفصل؛ هذا ما يثبتش كل موديل، منصة ولا حساب سحابة.

التجميعات اليدوية لـ GitHub Actions مفعّلة لجميع أحد عشر نوع توزيع. تبع [نتائج التجميع وتنزيلات المرشحين الموثقين](docs/CI_DISTRIBUTIONS.md); التوفر مسجل بشكل منفصل لكل منصة. المرشحين يختلفو عن الإصدارات الإنتاجية الموقعة. [سياسة الإصدار الرسمية](OFFICIAL_RELEASES.md) و [صفحة الإصدارات](https://github.com/TRON-ABS/Novera/releases). المرشحين الحاليين اللي معطلين التحديث يبقاو داخليين. الإصدارات العامة تتطلب آلية تحديث مُهيأة وموثقة; [فحوصات التوقيع على سطح المكتب ومتطلبات التشغيل المتبقية موثقة](docs/LAUNCH_STATUS.md).

## Novera 1.0.1

Novera 1.0.1 доступний для перелічених нижче платформ. Завантажте пакет для вашої системи або скористайтеся його підписаним каналом оновлення. Існуючі установки оновлюються, коли ви встановлюєте новий пакет або приймаєте оновлення.

- Безпека: суворіші рідні дозволи для віддалених сторінок, автентифікація для мережевих API та серверних інструментів, захищене секретне зберігання та міграція, безпечніший доступ до файлів/медіа, розбір електронних таблиць і сценарії побудови. Виявлені залежності оновлено; інші попередження відстежуються відкрито.
- Конфіденційність: для статистики та звітів про помилки потрібна окрема згода, і вони вимкнені за умовчанням. Збірки містять задокументовану цільову конфігурацію. Технічна діагностика відфільтрована; користувачі зберігають контроль над активацією.
- Локальна система: `llama.cpp v0.9.0` (`b12110`, `cd959bae99ff4bed22bef2604f45241c09bbb8c8`). Версія двигуна та версія додатка окремі. Початкові параметри моделі та реєстрацію моделі/проектора виправлено, включаючи помилку запуску, пов’язану з `kv_unified`. Існуючі персональні налаштування збережено.
- Мови: 24 додаткові мови та варіанти передають інтерфейс і перекладену колекцію README до 104, з 2,435 ключами інтерфейсу для кожного каталогу. Це покриття не підтверджує рідну редакційну якість або підтримку мовлення кожною мовою.
- **LFM3-Omni-2B Q4_K_M** — За умовчанням на комп’ютері та мобільному пристрої. Компактна модель для тексту, зображень і аудіо з використанням необхідного файлу `mmproj`. Завантажити: приблизно 1.39 GB для обох файлів. Виберіть його для більш легкої мультимодальної установки. Голосові функції залежать від платформи та двигуна. Довший контекст використовує більше пам’яті.
- **NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M** — Тільки текстова альтернатива для розмови, письма, інструментів і структурованих відповідей. Завантажити: близько 6.18 GB. Він потребує більше пам’яті, ніж LFM3-Omni, і сам не обробляє зображення чи звук. У голосових відповідях використовується системний голос. Вибирайте його для текстових завдань, коли у вас достатньо пам’яті. Звірте фактичні відповіді з джерелами.
- Для 1.0.1 LFM3-Omni-2B Q4_K_M з обов’язковим `mmproj-LFM3-Omni-2B-Q4_K_M.gguf` є рекомендацією за умовчанням для комп’ютера та мобільного пристрою; NVIDIA Nemotron-3.5-Bolt-E4B Q4_K_M залишається лише текстовою альтернативою. Початковий контекст – це 32,768 токенів на комп’ютері та 2,048 на мобільному пристрої. Довші контексти використовують більше пам'яті. Існуючі варіанти та параметри моделі зберігаються до тих пір, поки вони не будуть явно змінені.
- Голос: прямий локальний вхід із мікрофона для LFM3-Omni, безперервна розмова та автоматичне надсилання, чоловічий/жіночий голос для відповіді для аудіомоделей і системне мовлення для класичних моделей. Читання відповідей також працює для введених повідомлень і регенерації, незалежно від захоплення мікрофона. Маленька звукова кнопка дозволяє або вимикає читання.
- Статус мікрофона: зелений, коли доступний, червоний, коли зайнято, сірий, коли недоступний. Розпізнавання, перезапуск прослуховування, керування фокусом і видимий диктування виправлено. Рідна аудіомоділь мовлення наразі реалізована на Windows; інші платформи все ще потребують нативної перевірки та відповідної голосової підтримки.
- Веб: більш надійне виявлення запитів погоди, поточні вказівки, свіжі результати та цитати, а також відповіді, зосереджені на поточному запиті після використання інструменту. Виступ пропускає декоративні мітки джерел і посилання, зберігаючи видимі цитати. Мова відповіді та мовлення відповідає мові користувача, наскільки це підтримує обрана модель.
- Оптимізація: підготовка веб-пошуку у фоновому режимі, коли Інтернет увімкнено, спільний доступ до запуску служби, підготовка наступного фрагмента мовлення перед відтворенням і покращення безперервності речень. Французькі роки, десяткові числа та одиниці читаються більш природно. Затримка мережі та швидкість моделі все ще залежать від налаштувань.
- Комфорт: нижні елементи керування згортаються, а введення залишається видимим. Компактний мікрофон і елементи керування розкриттям, кнопка звуку під мікрофоном, чуйні налаштування музики та перекладені мітки компонентів покращують використання на маленьких екранах.
- Каталоги API: 43 профілі постачальників, включаючи TabbyAPI локально, з оновленим вибором чату та медіа. Нові записи включають GPT-6.1 Terra, Kimi K3.1 Pro, MiniMax M3.1 Flash, GLM 5.3 Flash, Hy4 і GPT Image 2.6, Gemini Omni 1.2, FLUX 3, де підтримуються. Оновлення більше не приховує результати, окрім десяти моделей. Дотримуються точних ідентифікаторів, регіональних кінцевих точок, приватних розгортань та імпортованих моделей.
- Перевірка: цільова програма, рідна бібліотека, публічний каталог і перевірки мови записуються в детальних примітках. Інтерфейс створено для Windows / macOS / Linux / Android / iOS. Ці інтерфейсні збірки не сертифікують рідні пакунки чи висновки на кожному пристрої.
- Наявність і завершені перевірки наведені нижче. Підтримувані функції залежать від апаратного забезпечення, доступу постачальника та платформи. Висновки безпеки та обмеження перевірки рідного пристрою залишаються задокументованими. Перед оновленням створіть резервну копію.

## Від першого запуску до результатів

**Наша автоматизація поєднує підготовку з повним робочим процесом виконання.** Novera обробляє технічні кроки, доступні для вибраної конфігурації, зберігаючи доступ до розширених елементів керування.

| Крок | З чим працює Novera |
| --- | --- |
| **1. старт** | Вибирає підтримувану системну мову під час першого запуску та зберігає ваші налаштування. Представляє початкові моделі та корисну інформацію про обладнання. |
| **2. Приготуйте** | Кероване встановлення пропонує текст, вбудовування, зображення, музику, відео та масштабування. Він попередньо переглядає компоненти, розміри та вільний простір перед вашим схваленням, а потім відстежує завантаження з прогресом, паузою/відновленням і перевіркою SHA-256. |
| **3. Налаштувати** | Реєструє моделі та їхні компоненти, готує відповідні профілі та звітує про необхідні залежності. Вбудовування пошуку починаються з CPU зі збереженим вибором CPU/GPU. Нові музичні профілі за замовчуванням використовують інструментальний режим. |
| **4. Зрозумійте прохання** | Автоматично направляє розпізнані запити на створення до тексту, зображення, музики чи відео. Ви також можете явно вибрати режим виведення та локальну або хмарну модель. |
| **5. Виконати** | Автоматична пам'ять чекає на активну роботу, звільняє непотрібні моделі та перезавантажує необхідні ресурси. Серія завдань 1–10 виконується в порядку та вивільняє ресурси перед наступним завданням. Хмарні постачальники використовують вибраний обліковий запис і конфігурацію. |
| **6. Отримайте та повторно використовуйте** | Зберігає мультимедійні файли в системних папках Novera, відображає результати та доступний час, а потім пропонує варіанти, бібліотеку, копіювання, експорт або спільний доступ до системи. Надсилання в інший додаток залишається за вами. |

Автоматизація охоплює інтегровані механізми та робочі процеси; він не робить кожну модель Hub виконуваною. Обладнання, встановлені компоненти та доступ постачальника визначають, що може працювати. Папки, зміни файлів і команди оболонки слідують за дозволами доступу в розмові.

## Концентратор і сумісні моделі

**GGUF, стандартні та квантовані Safetensors, ONNX і MLX**: досліджуйте моделі за завданням і вибирайте варіанти, сумісні з двигуном і вашим обладнанням.

| Сім'я | Підтримка в джерелі | Вимоги |
| --- | --- | --- |
| **GGUF** | Генерація тексту через llama.cpp; компоненти зображення та відео для підтримуваних профілів. | Архітектура, розпізнана вбудованим механізмом. |
| **Спліт GGUF** | Один варіант на повну серію, сумарний розмір, завантаження всіх фрагментів і перевірки розміру/SHA-256/заголовка. | Стандартні пронумеровані імена файлів; завантаження 500 GB не означає, що модель підходить до цього PC. |
| **Стандартний Safetensors** | Повні папки через Transformers, причинний текст на CPU або NVIDIA CUDA. | Конфігурація, токенизатор і всі необхідні фрагменти. |
| **ONNX Runtime** | Локальний імпорт числових/логічних графіків і підготовлений експорт тексту GenAI. | Перевірена повна папка; необхідна попередня/постобробка для конкретного завдання; [налаштування та обмеження](onnx-server/README.md). |

| **FP8 LLM / ModelOpt** | Нативне виконання CUDA для сумісного щільного експорту Llama/Qwen2/Qwen3 на тензор FP8. | Перевірки архітектури/тензора та справжнє дослідження ядра; [налаштування та обмеження](transformers-server/README.md#modelopt-fp8-and-nvfp4-llms). |
| **NVFP4 LLM / ModelOpt** | Упаковані блочні проекції 16 FP4 через рідні GEMM CUDA; окремо від зображення NVFP4. | Сумісний Blackwell GPU, підтримувані розміри/експорт і фактичний зонд ядра; ненавчені тестові моделі, протестовані на RTX 5070. |

| **EXL2** | Спеціальний завантажувач ExLlamaV2; потокове передавання, скасування та вивантаження протестовано на GPU. | Для перевіреного програмного стека слід явно вибрати бекенд CUDA Attention; потрібні повний чекпойнт моделі й достатній обсяг вільної VRAM. |
| **MLX** | Сумісні моделі на Apple Silicon. | Двигун MLX і підтримувана платформа. |

Hub тепер закріплюється **LFM3-1.7B** як його рекомендація LiquidAI для сумісних конфігурацій із варіантами Q4_K_M, Q6_K і Q8_0. Модель для першого запуску залишається тією, що вказана в інструкції з налаштування вище.

Фільтр ваги завантаження з **під 1 GB до 500 GB і вище**, а потім відсортуйте за апаратним забезпеченням, розміром, нещодавністю чи завантаженнями. Результати завантажуються поступово; фільтри застосовуються до вибраних моделей та їх варіантів за замовчуванням. Поради щодо пам’яті використовують доступні компоненти RAM/VRAM, контекст і супутні компоненти без подвійного підрахунку спільної пам’яті GPU.

AWQ 4-bit, GPTQ 4-bit, NF4 і INT8 кожен згенерував текст на RTX 5070 Laptop за допомогою крихітних ненавчених моделей, створених офлайн. Це підтверджує завантаження та виконання, а не якість чи продуктивність кожної моделі. **Ці доповнення є у вихідному коді: потрібні перебудова та сумісні залежності; це оновлення README не оновлює встановлений двійковий файл.**

**Виміряно на RTX 5070 Laptop:** Qwen2.5-0.5B-Instruct, контекст 2,048, токени запиту 272, генеровані токени 128, п’ять розігрітих прогонів: медіанна швидкість декодування **GGUF Q4_K_M 402.7 tokens/s · EXL3 4 bpw 312.5 · EXL2 4 bpw 146.9**. Тут не було продемонстровано жодних переваг у швидкості порівняно з GGUF. Квантування/калібрування відрізняється, і EXL3 не пройшов одну базову арифметичну перевірку; ці результати не є загальним рейтингом швидкості чи якості. [Повні вимірювання та обмеження](deliverables/exllama-2026-10-30/validation.md).

**TabbyAPI** – це додаткове, окремо кероване OpenAI-сумісне підключення до сервера, вимкнене за замовчуванням. Було перевірено виявлення автентифікованої моделі EXL3 і потокове передавання. Керований локальний маршрут ExLlama залишається відмінним. [Налаштування ExLlama і підключення TabbyAPI](transformers-server/README.md#exl3-first-exl2-second--nvidia-execution).

Сортування, адаптоване до апаратного забезпечення за замовчуванням, надає перевагу новішим випускам у межах того самого рівня сумісності та доступної пам’яті. Встановлені моделі не замінюються автоматично.

[Квантоване налаштування Safetensors](transformers-server/README.md#quantized-safetensors--source-integration-29-october-2026) · [Формати, пріоритети та перевірка](docs/SUIVI_MOTEURS.md)

Оновлені джерела доп **додаткові керовані компоненти в конфігураціях для Windows x64**: приватні середовища Python, закріплені профілі CPU/CUDA, оцінки та підтвердження перед завантаженнями, перевіркою, ремонтом і видаленням. Спеціальні шляхи інтерпретатора залишаються в розширених параметрах. Рідні двигуни GGUF зберігають наявні компоненти; для мобільних пристроїв і хмар не завантажується настільний Python/PyTorch. Три приватні профілі CPU/export були використані з синтетичними тестовими даними; Супроводжувач звітує про успішне використання робочого столу на 1 листопад 2026; Профілі GPU і чисте встановлення PC все ще потребують окремої детальної перевірки. [Профілі та межі тестування](docs/REPRISE_COMPOSANTS_GERES_80_LANGUES.md). Вбудовування стека в EXE відкладено.

## Статус проекту

На знімку екрана показано програму Windows, скомпільовану локально супроводжувачем. Зміни джерела, цільові тести та перевірка обладнання документуються окремо; це не перевіряє кожну модель, платформу чи хмарний обліковий запис.

Ручні збірки GitHub Actions увімкнено для всіх одинадцяти варіантів дистрибутива. Дотримуйтесь [результати збірки та перевірені завантаження кандидатів](docs/CI_DISTRIBUTIONS.md); доступність реєструється окремо для кожної платформи. Кандидати відрізняються від підписаних виробничих випусків. Вимоги до розподілу описані в [офіційна політика випуску](OFFICIAL_RELEASES.md) і [сторінка випусків](https://github.com/TRON-ABS/Novera/releases). Існуючі кандидати з вимкненим оновленням залишаються внутрішніми. Публічні випуски вимагають налаштованого та перевіреного механізму оновлення; [Перевірки підпису робочого столу та інші вимоги до запуску задокументовано](docs/LAUNCH_STATUS.md).
